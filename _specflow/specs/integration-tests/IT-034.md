# Integration Test for STORY-082: BP/PREV knowledge-surface visibility and consumption

Backfilled integration test for STORY-082 (Revive BP and PREV knowledge-surface visibility and consumption, decided by DEC-058).

## Test Reference

- tests/test_brief.py — exercises the visibility leg: the Knowledge surfaces block renders with zero counts and advisory dormancy hints when BP/PREV/FIND/CHL are all empty (test_knowledge_summary_reports_all_empty_surfaces, test_brief_renders_empty_knowledge_surfaces), BP/PREV dormancy hints fire when no active BP exists, and brief performs a single artifact-inventory discovery pass (test_brief_discovers_artifacts_once).
- tests/test_knowledge_lifecycle.py — exercises the consumption leg: TestBestPracticeChecklistLoading covers the canonical BP matcher (tag and applies_to matching), exclusion of nonmatching BPs and non-active statuses (draft is asserted; the active/approved whitelist also keeps superseded BPs out), checklist-run and CI context sharing one canonical match set, and the practice judged exactly once with no duplicated prompt content (test_review_prompt_does_not_duplicate_assembled_bp); the PREV lifecycle tests (pattern creation from findings, review feedback loop, done auto-extract) cover the reactive surface the BPs are symmetric with.

## Scope

DEC-058 revives the existing proactive (BP) and reactive (PREV) knowledge surfaces without adding a third learning system:
- visibility — brief reports BP/PREV/FIND/CHL counts, and the empty cupboard is self-evident
- real consumption — checklist assembly loads active/approved BPs through one canonical matcher, symmetric with PREV
- accounting-not-policing — advisory counts and hints only, no new gates
