# cascade-status as a real process: legal walk, closure hold, draft refusal and exit status (STORY-697 AC1, AC2, AC4)

tests/test_cascade_status_cli.py runs python -m specflow cascade-status in a subprocess on a project scaffolded from the real .specflow/schema maps. A verified STORY with --include-req walks an approved REQ and ARCH through implemented to verified, holds a second REQ at implemented because sibling STORY-002 is only implemented (naming it), refuses a draft DDD with the reason, leaves it draft, and the process exits 1; a run where every transition succeeds exits 0. On the v1.16.0 source (git archive HEAD) the first case fails: the process exited 0 after printing refused approved -> verified writes.
