# Integration Test for ARCH-016: Init Upgrade Engine

## Test Cases

- [ ] Given an initialized project with user-modified config values, when `specflow init` re-runs, then the user's values are preserved and new default keys are added
- [ ] Given an initialized project, when `specflow init` re-runs without `--force`, then `state.yaml` is not overwritten and the merge path is taken
- [ ] Given an initialized project, when `specflow init --force` runs, then config, state and schemas are first backed up under `.specflow/cache/backups/<timestamp>/` and the project ends in a fresh-init state
- [ ] Given a schema file the user changed or a pack added, when schemas are refreshed without `--force`, then the changed file is preserved with a hint, a pack-added schema is never classified as drift, and missing framework schemas are written
