# Integration Test for ARCH-021: Skill Continuity Layer

## Test Cases

- [ ] Given a discovery session where a challenge technique surfaces a dropped requirement or an implicit assumption, when the discover skill's challenge step completes, then it creates a DEC titled "Dropped: <summary>" (approved, rationale in the body) or "Assumption: <text>" (draft, consequence if wrong); given no significant challenge result, then no DEC is created
- [ ] Given several REQs, when the discover summary is presented, then the skill asks whether any REQ depends on another and records each named dependency as a REQ-to-REQ `derives_from` link; given none, then no inter-REQ link is created
- [ ] Given a project whose config sets `project.domain` and `project.domain_tags`, when the plan skill reads context, then it frames the architecture discussion with them and loads the DECs discovery created; given no domain, then it proceeds without domain framing
- [ ] Given a discovery session that leaves REQs in `draft`, when it ends, then the exit message lists the draft REQ IDs with the `specflow update <ID> --status approved` command and recommends `/specflow-plan` after approval
- [ ] Given the shipped discover and plan SKILL.md files, when `tests/test_discovery_plan_continuity.py` runs, then each behavior above is present in the skill text
