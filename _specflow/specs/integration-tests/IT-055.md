# Integration Test for ARCH-035: Practice spine: BP anatomy, provenance, lifecycle, and deterministic validation

## Test Cases

- [ ] Given a best practice carrying all five anatomy sections and a resolvable provenance, when `specflow practices validate` runs, then it passes; given a malformed one, then it is reported deterministically and no network socket is opened
- [ ] Given legacy BPs without provenance, when `specflow practices migrate --dry-run` runs, then it prints the would-stamp set and writes nothing; when it runs for real twice, then the second run stamps nothing (idempotent)
- [ ] Given a BP with both an applicability predicate and tags, when the loader resolves BPs for an artifact, then applicability decides before the tag fallback
- [ ] Given the shipped dogfood BPs, when the new loader and the legacy tag/link path both resolve them, then they select the same set
- [ ] Given `specflow init`, a schema refresh, or a pack apply/refresh on a project with legacy BPs, when it runs, then those BPs are stamped with provenance
