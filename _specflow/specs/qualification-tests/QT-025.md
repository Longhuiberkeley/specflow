# Qualification Test for REQ-024: Output File Traceability

## Test Cases

- [ ] 1. Given an artifact with an `output_files` field containing a list of file paths, when the artifact is created or updated, then the system **shall** accept and persist the field in YAML frontmatter.
- [ ] 2. Given an artifact with an `output_files` entry pointing to a non-existent file path, when `specflow artifact-lint` is executed, then the system **shall** report a warning listing the missing file.
- [ ] 3. Given an artifact with an `output_files` entry containing a glob pattern (e.g., `output/YY_MM_DD_*.json`), when `specflow artifact-lint` is executed, then the system **shall** skip the existence check for that entry without reporting a warning.
- [ ] 4. Given a file path in `output_files`, when the system validates the artifact, then the system **shall** resolve the path relative to the project root directory.
- [ ] 5. Given a user running `specflow update <ID> --output-files "path1,path2"`, when the command completes, then the system **shall** replace the artifact's `output_files` field with the provided list.
- [ ] 6. Given an artifact without an `output_files` field, when `specflow artifact-lint` is executed, then the system **shall** produce no warnings related to output files.
