# Unit Test for STORY-083: Refresh safety contract

Backfilled unit test for STORY-083 (Refresh active pack assets safely — REQ-032 / ARCH-022): the `specflow refresh` safety contract.

## Test Reference

- tests/test_refresh_lints.py::TestRefreshCommand — the story's safety acceptance criteria verbatim:
  - Preview changes: `test_dry_run_does_not_create_skill_files`, `test_schemas_dry_run_reports_without_writing`, `test_active_pack_dry_run_reports_without_writing` — dry-run is a pure preview: no files written, no legacy dirs deleted.
  - Preserve without force: `test_active_pack_refresh_preserves_existing_without_force` — a user-edited managed file is kept and reported as "preserved".
  - Force refresh: `test_active_pack_force_refreshes_schema` — only `--force` overwrites a stale managed file, and refresh never writes into `_specflow/`.
  - `test_no_skills_skips_skill_install` — `--no-skills` skips skill installation entirely.

Note: the same file also hosts TestSpikeLifecycle and TestSourceDrift, which belong to separate lint contracts; they run because the verify_command executes the whole file, but they are not part of this documented scope.

## Scope

STORY-083's acceptance: preview changes; preserve _specflow artifacts; require force for ambiguous user edits; keep context idempotent; cover behavior with tests. This contract documents the refresh-command safety behaviors (preview / preserve / force) exercised by TestRefreshCommand. The context-injection idempotency part of the story lives in tests/test_autoresearch_pack.py (TestPackContextInjection) and is not claimed here. UT-057/UT-061 already run test_refresh_lints.py, but their documented scopes are different contracts (DDD-023 adds_skills semantics; DDD-027 autoresearch pack detailed design) — a dedicated contract for STORY-083 matches house convention.
