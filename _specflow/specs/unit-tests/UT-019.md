# Unit Test for DDD-013: Provider-Agnostic CI Gate Detailed Design

## Test Cases

- [ ] Given no team configuration or empty roles, when the RBAC check runs, then it is solo mode and authorizes the transition
- [ ] Given roles mapped by explicit email, when an allowed status transition is checked, then it exits 0; given a denied transition, then it exits non-zero; given no explicit email, then it falls back to the git author email
- [ ] Given generated CI for a provider, when `specflow ci generate` runs, then specflow-only jobs bootstrap from a version-pinned git source and never use `uv run`, and the ci-gate job diffs the base against the PR head
- [ ] Given an existing hand-edited workflow, when `ci generate` re-runs, then it is preserved and the flags are named; given `--force`, then it is backed up before overwrite; given `--dry-run`, then nothing is written
