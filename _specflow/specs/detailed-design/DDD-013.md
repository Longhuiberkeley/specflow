# Provider-Agnostic CI Gate Detailed Design

## Function

The CI gate enforces RBAC policies on artifact status transitions in pull requests using only git operations, with provider-specific knowledge confined to adapter templates. The command `specflow ci-gate --base <ref> --head <ref>` runs as a CI pipeline step, diffs the two refs for changes under `_specflow/**/*.md`, detects status transitions by parsing frontmatter from both refs, and authorizes each transition against the team role policy. Transitions to verification statuses additionally enforce independence (verifier must not be the implementer).

## Algorithm

The gate operates in five steps. Step 1: Run `git diff --name-only base..head` and filter to `_specflow/**/*.md` files. Step 2: Extract the commit author email from `git log --format=%ae`. Step 3: For each changed file, use `git show ref:path` to parse frontmatter from both base and head refs, extracting the `status` field from each. Step 4: For each detected status transition, call `authorize_status_transition(root, artifact_id, new_status, author_email)` which checks the team's `.specflow/team.yaml` role assignments. Step 5: For transitions to `verified` or `approved` status, call `check_independence(root, artifact_id, author_email)` which uses `git log --format=%ae -- <filepath>` to verify the author is not the same person who previously modified the artifact.

## Error Handling

A solo-dev fast path skips all authorization when no team roles are configured, returning success immediately. If `git show` fails for a ref (e.g., the file was added in the head), the gate treats the base version as empty (new artifact). If the team.yaml is malformed, the gate exits with code 2 and a descriptive error message. Any unhandled exception during authorization is caught and reported as a gate failure with exit code 1, preventing silent bypass.

## Implementation

The gate command lives in `src/specflow/commands/hook.py` and shares RBAC functions (`authorize_status_transition`, `check_independence`) with the pre-commit hook in the same module. The pre-commit hook obtains transitions from the git staged index, while the CI gate obtains them from `git diff` between two refs. Provider-specific CI workflow templates (GitHub Actions, GitLab CI) are generated by `specflow ci generate` using the adapter registry pattern, where each adapter registers via a class decorator and provides a `get_workflow_template()` method.
