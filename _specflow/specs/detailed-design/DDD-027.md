# Autoresearch pack — schema field contracts, CLI dispatch, context injection, domain-aware lint

# Detailed design — autoresearch pack capability surface

Refines ARCH-027 (the schema-driven autoresearch pack surface). Specifies the
four schema field contracts, the CLI subcommand dispatch, the idempotent
context-injection mechanism, the `--set` write path, the domain-aware lint
algorithm, and the multi-objective diversity selection.

## 1. Schema field contracts (the single source of truth)

Each schema YAML is the contract; the CLI, lint, and protocols all read from
these. The enhanced-logging fields (REQ-035) and the v0.2.0 fields
(REQ-AUTORESE-d684) coexist on the same schemas:

| Schema | v0.2.0 fields | Enhanced-logging fields |
|---|---|---|
| `competition.yaml` | `auxiliary_metrics` | `objective_type`, `success_criteria`, `domain`, `pre_check_command`, `post_check_command`, `noise_characterization`, `goals` |
| `experiment.yaml` | `auxiliary_metrics` | `parameters`, `model_origin`, `sweep_results`, `checks`, `baseline_note`, `diversity_metrics`, `failure_analysis`, `hypothesis`, `hypothesis_outcome` |
| `loop.yaml` | — | `goal`, `required_findings`, `termination_suggestions` |
| `finding.yaml` | — | `deployability`, `safety_assessment`, `applies_to_domain` |

All fields are OPTIONAL and freeform-typed in the schema (YAML dicts/strings);
the lint lens (§5) is what gives the domain-recommended ones teeth.

## 2. CLI subcommand dispatch (`commands/autoresearch.py`)

`plan|run|review|leaderboard` resolve their target COMP via `_resolve_comp`
(`--competition` selects; else single active COMP; else error). `run` resolves
the active LOOP via `_resolve_loop` (one `running`, else one `draft`).
`leaderboard` accepts `--group-by model_origin` and `--show-family` as
read-only projections over EXPT fields. Multi-COMP repos use `--all`. Every
mutation (LOOP status, FIND creation) goes through `art_lib.create_artifact` /
`update_artifact`, never direct file writes.

## 3. Idempotent context injection (`inject_pack_context`)

`pack.yaml.context_snippet` is injected into each platform's instruction file
(named by `platforms.yaml.instruction_file`) between idempotent sentinel
markers. Re-runs detect the sentinels and replace the block in place rather
than appending duplicates. Design choice: the sentinels are stable strings
(unique to the pack) so a pack update cleanly rewrites its own block without
touching hand-authored content outside the markers.

## 4. The `--set KEY=VALUE` write path

`specflow create` / `update --set KEY=VALUE` parses each token into a
frontmatter key path, JSON-decodes values that look like JSON, and routes the
dict into `create_artifact` / `update_artifact`. Reserved keys (`status`,
`type`, `links`, …) are rejected with a pointer to the dedicated flag. This is
the mechanism the autoresearch protocols use to populate the schema fields from
the CLI — without it, the documented LOOP cannot run deterministically.

## 5. Algorithm — domain-aware lint (`artifact_lint._check_autoresearch_logging`)

Algorithm: for each EXPT under a COMP that declares a `domain`, look up
`_domain_recommended_fields(domain)` and warn on any missing recommended
field (e.g. quant → `auxiliary_metrics` with drawdown/sharpe). Warn (not block)
on a discarded EXPT lacking `failure_analysis`. Warn on a completed LOOP with
zero FINDs. The warnings are scope-honest (BP-006): they surface what the
schema recommends for the declared domain without mandating a single canonical
field set.

## 6. Multi-objective diversity selection

`objective_type` selects the keep policy: `single` keeps the best metric;
`family_of_good` uses `diversity_metrics` to prefer keeps that are uncorrelated
with existing keeps (greedy: rank by primary, then walk the ranked list adding a
candidate only if its diversity vector is sufficiently uncorrelated); `pareto`
keeps the non-dominated set. The leaderboard's `--show-family` renders the
kept family grouped by `model_origin`. No separate engine path — the policy is
a read over the same EXPT fields.
