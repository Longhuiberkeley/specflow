# Recovery Primitives Implementation

## Function

The recovery primitives module provides the building blocks for SpecFlow's error recovery and state restoration subsystem. It implements atomic file operations, transactional multi-file writes, and rollback capabilities that allow SpecFlow to recover from interrupted operations such as partial artifact creation, failed wave execution, or corrupted index files. The primitives are consumed by the executor, scaffold, and lock modules to ensure that any multi-step filesystem mutation can be cleanly undone if a subsequent step fails.

## Data Structure

The core data structure is a `Transaction` object that accumulates file-system operations (create, write, delete) and tracks original content for rollback. Each operation records the target path, the operation type, and a snapshot of the file's prior state (or `None` for creates). The transaction maintains an ordered log so that rollback proceeds in reverse order, restoring the filesystem to its pre-transaction state. A `RecoveryPoint` dataclass captures the project root, timestamp, and list of affected paths for crash-recovery diagnostics.

## Error Handling

When a transaction encounters an I/O error mid-way, it immediately initiates rollback by replaying the operation log in reverse. Files that were created are deleted; files that were overwritten are restored from their snapshots. If rollback itself fails (e.g., disk full), the module writes a `.specflow/recovery/<timestamp>.log` file with the list of partially-applied operations so that a future `specflow rebuild-index` or manual intervention can complete recovery. All filesystem mutations use atomic write-then-rename patterns to avoid half-written files visible to other processes.
