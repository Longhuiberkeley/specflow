## Rationale
Detailed design for ARCH-034 / REQ-043: how the deterministic reassessment signal, the evidence/priority fields, and the boundary-review contract are realized in the CLI, schemas, lint, and skill surfaces. The reassessment predicate is bounded to the last three affected experiments and reads an anchored, novel `research_progress` claim or a measured new best — never outcome labels, repeats, non-finite numbers, or older keeps.

## Component Responsibilities

- `specflow/commands/autoresearch.py` — `_tail_run()` returns the consecutive tail for a key; `_progress_note()` validates the `{evidence_ref, finding, next_decision}` shape; `_evidence_ref_is_anchored()` ties the ref to the current EXPT narrowly (ID exactly or with an explicit `#fragment`; recorded `commit` exactly or as a ≥7-char hex abbreviation; or an output path logged outside `research_progress` that exists); `_note_repeats()` rejects claims/refs already present in history, inside or outside the window, with ref schemes normalized (`commit:x` ≡ `x`); `_keep_shows_improvement()` accepts a keep only as a new best primary `metric_value` per direction, with a finite correctly-signed `delta` as the fallback only when no comparable metric exists (`_numeric()` rejects NaN/Infinity); `_window_has_progress()` evaluates only the tail's last `_RECENT_WINDOW` (3) EXPTs against the full preceding history. `_assess_loop()` emits the single `reassess` warn when either tail is ≥3 and its window is evidence-free, an `agenda` warn when the reasoning is absent, and a `progress` advisory when a prioritized direction lacks a progress note. `_open_agenda_directions()` filters `deprioritize`/`blocked` while keeping `revisit` open. `_run_log()` validates `--research-progress` JSON (object with three non-empty strings; `research_progress` is reserved against `--set`) and writes it onto the EXPT. The `run` protocol text teaches coherent hypotheses, evidence/priority, and the recent-window record.
- `specflow/commands/artifact_lint.py` — accepts `invalid` in the `hypothesis_outcome` guidance, requires `failure_analysis` alongside it, and warns when a present `research_progress` does not have the documented shape (shape-only; anchoring/novelty stay in `status`).
- Pack schemas — `experiment.yaml` documents the evidence vocabulary and the `research_progress` shape/anchoring rules; `loop.yaml` documents the agenda entry shape (`priority`, `progress`) and points at the EXPT record.
- Skill references — `autonomous-loop-protocol.md` owns the invariants (evidence vs priority, recent-window reassess-on-evidence, runtime/LOOP/project-cycle terminology); `finding-generation-protocol.md` owns the FIND-side evidence vocabulary and the `sensitive` robustness tag; `competition-setup-protocol.md` owns the SPIKE/FIND rule for nonmetric work; `crash-recovery-protocol.md` owns the evidence-free-streak walk.

## Algorithm

1. Order EXPTs by `(iteration, created, id)`.
2. Take the consecutive same-category tail and the consecutive non-kept status tail.
3. Reduce each tail to its last 3 artifacts (the bounded recent window). A keep outside this window is invisible to the predicate.
4. For each window EXPT (in order), with all earlier EXPTs as history:
   a. accept an anchored, non-repeated `research_progress` note (evidence_ref → EXPT ID exactly or `#fragment` / recorded commit exactly or ≥7-char hex abbreviation / logged existing path outside the note; finding and ref novel against history); or
   b. accept `status: kept` only when a finite `metric_value` beats the best prior kept value per `COMP.metric_direction` (the first measured keep counts); when no comparable metric exists, accept a finite `delta` with the improvement sign. Non-finite numbers never count.
5. Warn (`reassess`, exit 3) when either tail has length ≥3 with no evidence movement in its window; otherwise emit an ok signal. The signal never blocks and never changes a direction's lifecycle by itself.
6. Agenda presence is checked (non-empty); direction count is not a gate. A prioritized direction without `progress` raises an advisory, not a warn.

## Invariants

- Exit codes: 0 clear, 3 warn, 1/2 fail; only git preconditions, concurrent running LOOPs, and exhausted budget fail.
- The predicate checks existence, anchor, and novelty only; it never claims the evidence is true — the agent reads the cited source.
- Agenda fields are additive and optional: entries without `priority` behave as open; `pursue`/`revisit` stay open, `deprioritize`/`blocked` do not.
- `research_progress` is optional; absent or malformed records are read conservatively as no evidence (no crash, no optimistic pass).
- Anchor matching is boundary-safe: `EXPT-001` never matches `EXPT-0010`; `commit:` and sub-7-char prefixes never match; the note cannot certify its own path.

## Interface

The interface is the existing CLI surface (`autoresearch status|log|run`, `update --set`) plus the optional agenda fields and the new `autoresearch log --research-progress '<json>'` producer; no new commands, modes, or personas.

## Data Flow

EXPT logs (`hypothesis_outcome`, optional `research_progress`, `status`/`delta`/`metric_value`) → per-tail recent-window predicates → `status` signal → operator/agent records `priority` + `progress` on the agenda direction → next LOOP reads it through `knowledge_input` and condensation briefs.
