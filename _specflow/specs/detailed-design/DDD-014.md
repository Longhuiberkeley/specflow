# V-Model Test Scaffolding Detailed Design

## Function

The V-model test scaffolding engine creates UT, IT, and QT test stub artifacts from implemented spec artifacts using a deterministic type mapping with zero LLM tokens. Given a requirement (REQ), it generates a qualification test (QT); given an architecture (ARCH), it generates an integration test (IT); given a detailed design (DDD), it generates a unit test (UT). Each generated stub includes a `verified_by` link back to the source spec and, for QT stubs, pre-populated test case placeholders extracted from the source requirement's acceptance criteria.

## Algorithm

The command flow proceeds in four steps. Step 1: Discover all artifacts and build the ID index. Step 2: If `--from ID` is provided, scope to that single artifact; otherwise scan all spec artifacts with `implemented` or `verified` status that lack a verification pair. Duplicate prevention scans all existing artifacts for `verified_by` links pointing to the source spec before creating. Step 3: Call `create_artifact()` with the mapped test type, a derived title (e.g., "Unit Test for DDD-007: Recovery Primitives"), draft status, and the `verified_by` link. Step 4: For QT stubs, parse the source REQ's "Acceptance Criteria" section using a state-machine line parser that collects numbered items, bullet items, and Given/When/Then BDD lines into test case placeholders.

## Data Structure

The V-model pairing is defined by three static dicts: `TYPE_LABELS` (spec type → test prefix), `TEST_TYPE_NAMES` (spec type → test type string), and `TEST_LEVEL_LABELS` (spec type → human-readable label). The canonical `V_MODEL_PAIRS` mapping in `lib/artifacts.py` is the single source of truth shared by the scaffolding engine, the coverage lint check, and `status.py`. Generated test bodies contain a markdown heading and a "Test Cases" section with checkbox items.

## Precondition

The source artifact must have status `implemented` or `verified`. If the status is `draft` or `approved`, the command warns the user and exits without creating a stub. The source artifact type must be one of `requirement`, `architecture`, or `detailed-design` — work types (story, spike, decision) have no V-model pair.
