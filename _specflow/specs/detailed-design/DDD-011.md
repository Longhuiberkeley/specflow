# CLI Core Detailed Design

## Function

The CLI core is the programmatic entry point for all SpecFlow operations. It uses Python's `argparse` module to register 29 top-level subcommands (init, status, create, update, trace, artifact-lint, generate-tests, go, done, baseline, ci-gate, etc.) and dispatches each to a dedicated command module under `src/specflow/commands/`. Each command module exposes a `run(root, args)` function that receives the resolved project root and the parsed argument namespace. The core handles project-root discovery by walking up from the current directory to find a `.specflow/` marker directory.

## Data Structure

The dispatch table is a dict mapping subcommand names to tuples of `(module_name, help_string)`. Lazy imports ensure that only the invoked command's module is loaded, keeping startup time minimal. The `args` namespace is passed as a plain dict via `vars(args)` to decouple command modules from argparse internals. The project root is resolved once by `_find_project_root()` and passed to every command, ensuring consistent path resolution.

## Signature

```python
def cmd_<name>(args: argparse.Namespace) -> int:
    from specflow.commands import <module> as cmd
    root = _find_project_root()
    return cmd.run(root, vars(args))
```

Each command wrapper follows this exact signature. The return value is an integer exit code: 0 for success, 1 for user-facing errors, 2+ for internal errors. The main `cli()` function catches `KeyboardInterrupt` and returns 130.

## Implementation

The entry point is `src/specflow/cli.py`, which defines `main()` as the console script entry point (registered in `pyproject.toml` as `[project.scripts] specflow = "specflow.cli:main"`). Subcommands are grouped into discover, plan, execute, review, release, CI, data, hygiene, and recovery categories. The `--verbose` flag enables debug logging. The `--root` flag overrides project-root discovery for CI environments where the working directory differs from the project root.
