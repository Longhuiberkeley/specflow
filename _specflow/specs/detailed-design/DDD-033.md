# ontology.yaml schema and kind/orientation resolution

## Data model
```yaml
types:
  - name: requirement
    prefix: REQ
    dir: specs/requirements
    kind: claim                      # claim | work | evidence | judgment
    kind_by_attr: {}                 # decision: {dec_kind: {change_record: evidence}}, default claim
    spec_level: 1                    # requirement 1, architecture 2, detailed-design 3, tests 4
    v_pair: qualification-test       # V-model partner type, if any
    normative_fields: [title, body, acceptance_criteria]   # fp2 covers these
lifecycles:
  requirement:
    entry: draft
    terminal: [deprecated, superseded, cancelled]
    transitions: {approved: [draft], implemented: [approved], verified: [implemented], ...}
roles:
  - name: verified_by
    predicate: verifies              # canonical predicate name
    orientation:                     # per source kind/type -> (subject, object) mapping
      test: [source, target]         # UT verified_by X  => verifies(UT, X)
      claim: [target, source]        # REQ verified_by UT => verifies(UT, REQ)
    targets: {claim: [unit-test, integration-test, qualification-test, experiment]}
    judged: true                     # derives_from stays judged: false
    upstream_bearing: true
    synonyms: [verifies, tested_by]
    inverse: verifies
    stamps_fingerprint: true
```

## Resolution rules
- `kind(artifact)` = `kind_by_attr[type][attr value]` if declared and present, else `types[type].kind`. Pack types without `kind` default from `category`: spec → claim, research → per-name table (COMP, LOOP work; EXPT, RUN, MON evidence; FIND, HAZ claim), ops → evidence.
- Canonical edge for stored link (S, role, T): look up `roles[role].orientation[kind(S) or type(S)]`; emit `predicate(subject, object)`. Unknown role or orientation → `unknown_role` finding, never a crash.
- Overlay merge order: packaged ontology → pack schemas → consumer `.specflow/schema/*.yaml`. Overlays may add types, fields, statuses and roles; they may not change a core role's predicate or orientation (rules check fails).
- fp2 = `fp2:` + sha256 over the concatenation of `normative_fields` values in declared order, normalised (strip, LF). Missing field contributes the empty string. Independent of the v1 `sha256:` body fingerprint.

## Interfaces
- `load_ontology(root) -> Registry` (frozen dataclass; raises `OntologyError(path, reason)`).
- `Registry.kind(artifact)`, `Registry.canonical_edge(link, source)`, `Registry.lifecycle(type)`, `Registry.targets(type, role)`, `Registry.fp2(artifact)`.
- Derived tables for legacy call sites: `TYPE_TO_DIR`, `PREFIX_TO_TYPE`, `V_MODEL_PAIRS`, `ROLE_TARGET_MATRIX`, `VALID_STATUS_ORDER`, `TERMINAL_STATUSES`, `known_meta` (all computed, none hand-written).

## Error handling
Malformed YAML, duplicate prefix, cyclic lifecycle without terminal, role with zero or two orientations, matrix row naming an undeclared type: all raise `OntologyError` at load; the CLI boundary prints path and reason and exits 3.
