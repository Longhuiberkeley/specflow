# pack.yaml adds_skills field — semantics and install behavior

## Function

The `adds_skills` field in `pack.yaml` allows packs to ship AI platform skills (SKILL.md files and references) that are installed into the user's platform-specific skills directory during `specflow init --with-pack`. This extends the pack system beyond schemas, directories, checklists, and standards to include conversational skill definitions.

## Schema extension

`pack.yaml` accepts a new optional list field:

```yaml
adds_skills:
  - <skill-name>
  - <skill-name>
```

Each name must correspond to a subdirectory of `pack_root/skills/<name>/` containing at minimum a `SKILL.md` file.

## Install behavior (in apply_pack)

After existing steps 1-4 (schemas, directories, checklists, standards), insert Step 5:

```
Step 5 — Install pack skills:
  platform_code, _ = platform.detect_platform(root)
  if platform_code is None: skip (warn user)
  skills_dir = platform.get_skills_dir(root, platform_code)
  for skill_name in manifest.get('adds_skills', []) or []:
    src = pack_root / 'skills' / skill_name
    dst = skills_dir / skill_name
    if not dst.exists():
      shutil.copytree(src, dst)
    # else: preserved (no-overwrite policy)
```

## Return value

`apply_pack()` result gains a `skills_added: [<name>...]` field reporting which skills were newly installed.

## Edge cases

- **No platform detected**: skip skill copy, warn user ("Pack X declares skills but no AI platform detected; install manually")
- **Skill already exists**: preserve user version (consistent with schemas/standards/checklists)
- **Skill directory missing in pack**: hard error (manifest is wrong)
