# Source File to Artifact Reverse Mapping Algorithm

Detailed design for the reverse impact engine that maps source code and data product changes back to spec artifacts.

## Data Structures

```python
@dataclass
class FileArtifactMatch:
    file_path: str
    artifact_id: str
    match_type: str  # "literal" | "glob"
    pattern: str     # the output_files entry that matched
```

## Algorithm: Build Output File Index

`build_output_file_index(root: Path) -> dict[str, list[tuple[str, str]]]`

1. Scan all artifact directories for .md files.
2. For each artifact, parse YAML frontmatter, extract `output_files` list.
3. For each path in `output_files`:
   a. If path contains glob characters: store as-is with type "glob".
   b. If literal: normalize path (resolve ".", "..", trailing slashes), store with type "literal".
4. Build reverse map: `normalized_path -> [(artifact_id, match_type, pattern)]`.
5. Return the reverse map.

## Algorithm: Reverse Impact

`query_reverse_impact(root: Path, changed_files: list[str], index: dict) -> list[FileArtifactMatch]`

1. Initialize `matches = []`.
2. For each changed file:
   a. Normalize the file path relative to root.
   b. Check literal match: if path in index, add all mapped artifact IDs to matches.
   c. Check glob match: for each glob pattern in index, test via `_glob_match()` which supports `**` recursive globs. If match, add to results.
3. Deduplicate matches by (file_path, artifact_id) pair.
4. Return matches (pure query — no file mutation).

`flag_suspects_from_matches(root: Path, matches: list[FileArtifactMatch]) -> list[str]`

1. For each unique artifact_id in matches: set `suspect: true` on the artifact.
2. Propagate downstream recursively via `_find_all_downstream_recursive()`.
3. Return list of flagged artifact IDs.

`reverse_impact(root, changed_files, index) -> list[FileArtifactMatch]` is a convenience wrapper that calls query then flag.

## Algorithm: Glob Pattern Detection

`is_glob_pattern(path: str) -> bool`

1. Return `any(c in path for c in "*?[")`.

## Algorithm: Glob Matching Against Changed Files

`_glob_match(file_path: str, pattern: str) -> bool`

1. If pattern contains `**`: convert to regex where `**` matches zero or more intermediate directories.
2. If pattern does not contain `**`: delegate to `fnmatch.fnmatch(file_path, pattern)`.
3. Return boolean match result.

## Integration with change-impact Report

1. Extend `change_impact.py` report to include a new section: "Source File Impact".
2. By default, `specflow change-impact` queries matches read-only (no suspect flagging).
3. `specflow change-impact --flag` additionally flags matched artifacts and propagates suspects.
4. Format: for each affected artifact, list which files changed and which `output_files` pattern matched.

## Error Handling

- Empty `output_files` on all artifacts: reverse impact is a no-op, return empty list.
- Malformed glob pattern in `output_files`: log warning, skip that entry.
- Permission error reading artifact files: skip that artifact, log warning.

## Implementation Files

- `src/specflow/lib/impact.py` — build_output_file_index(), reverse_impact(), match functions
- `src/specflow/commands/change_impact.py` — extended report with source file section
- `src/specflow/commands/document_changes.py` — pass source file changes to reverse_impact()
