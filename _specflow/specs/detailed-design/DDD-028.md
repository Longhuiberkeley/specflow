# Deferred lifecycle capabilities — command-surface detailed design

# Detailed design — deferred lifecycle capability command surfaces

Refines ARCH-028 (the six accounting-based lifecycle commands). Specifies each
command's data model, algorithm, and exit-code contract. All six compose the
existing artifact graph; none introduces a new type or link role.

## 1. phase-set — reverse-lifecycle accounting (`commands/phase_set.py`)

`specflow phase-set <phase> --reason` appends a transition record to execution
state history. Each record carries `{from, to, reason, ts, direction}` where
`direction` is `forward` or `rewind` (derived by comparing phase order). The
command NEVER rejects a transition — it records both directions faithfully.
When leaving the `executing` phase, execution state (`in_progress`, `queued`,
`wave`) clears. Exit 0 always (accounting). The history is the evidence; the
operator is the authority.

## 2. Algorithm — rtm bidirectional traceability matrix (`commands/rtm.py`)

`_children_of(id, type, roles, artifacts)` is the core walk: collect artifacts
of `type` whose links match `roles` and target `id`. REQ→ARCH→DDD uses
`{derives_from, refined_by}`; →STORY uses `{implements}`; STORY→tests uses
`{verified_by}`. The matrix prints one row per REQ with columns for each level
and per-column gap markers (✓/—). `--gaps` filters to rows with any gap.
Formats: table (default), markdown (`--format markdown`), csv (`--format csv`).
An orphan-test footer lists tests linked to nothing. Pure read; exit 0.

## 3. rbac check — CODEOWNERS resolution (`commands/rbac_check.py`)

Resolve the current git author (`git config user.email`), match against
`.specflow/rbac.yaml` role bindings (driven by `CODEOWNERS` path patterns),
and report the resolved role(s). `rbac check --transition <from>:<to>:<type>`
verifies the transition is permitted for the resolved role. Single-user
projects (no rbac.yaml / author unmatched) print a clear not-active message
and exit 0 — never a blocker for a solo maintainer.

## 4. supersession — link role + status pairing

The new artifact links `supersedes` → the old artifact FIRST; then the old
artifact's status moves to `superseded` (allowed from approved/implemented/
verified). docs-staleness warns on any doc citing a superseded artifact. The
`supersedes` role and `superseded` status already existed in the D-18 frozen
vocabulary; this capability exercised them end-to-end. The pairing order
(new→old link before old status change) keeps the graph navigable at every
intermediate state.

## 5. AC / NFR quality gates (`artifact_lint`)

`count_acceptance_criteria_items(req)` parses the Acceptance Criteria section
(list items / numbered items) and returns a count. An EMPTY section is a
BLOCKING lint error (a REQ with no acceptance criteria is not a requirement).
An NFR REQ (non_functional_category set, not `functional`) without a numeric
threshold in its body is a NON-BLOCKING scope-honest warning. Lint is invoked
by the release gate; lint does not become the gate — the structural exit-code
drivers remain in `check_coverage`.

## 6. multi-host detection (`commands/init.py`, `commands/refresh.py`)

`init` scans for known host markers (`.claude/`, `.cursor/`, `.windsurf/`,
`.codex/`, `.opencode/`, …) and WARNS when ≥2 are detected, naming them.
`refresh --all-platforms` iterates every detected host's skill directory and
re-syncs from the shipped templates. Detection is best-effort and advisory;
it never blocks init.
