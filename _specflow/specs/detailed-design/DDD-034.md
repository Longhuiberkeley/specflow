# Index store: allocation, cache, crash and re-run invariants

## Scope
The artifact index store: `_index.yaml` per artifact directory, id allocation, `rebuild-index`, `renumber-drafts`, `artifact-lint --fix`, merge and split, plus the PREV, baseline and impact-log allocators and the mutation lock's stale-break path.

## Invariants
- I1 NoDupId: no two artifact files carry the same frontmatter id.
- I2 NoOverwrite: a create that reports success never changes the bytes of any other existing file.
- I3 NoReuse: an id once allocated, including deleted and quarantined ids, is never allocated again.
- I4 IndexIsCache: after any sequence of operations without a crash, the index keys equal the ids on disk and next_id exceeds the largest id ever allocated.
- I5 RerunConverges: a crash at any write, whether the write raises or leaves a torn file, followed by a re-run of the same command, ends in the same state as an uncrashed run.
- I6 MutualExclusion: at most one process ever believes it holds the mutation lock, including through the stale-break path.

## Design
- Linearisation point: `open(path, 'x')` on the artifact file; retry with the next candidate on FileExistsError.
- Candidate id: max(ids on disk via rglob, quarantine ids, index next_id) + 1.
- Index as cache: `_read_index` rebuilds from disk under the lock on parse failure or conflict markers; `rebuild-index` preserves quarantine so I3 holds.
- One mutation lock: `locks.mutation_lock(root)` wraps every writer; `atomic_write(path, text)` asserts the lock is held and writes through a temp file plus `os.replace`.
- Renumber: plan from disk and index, refuse if any target exists or the branch is a feature branch, write a journal before the first rename, resume from the journal on re-run.
- Stale break: `fcntl.flock` on POSIX; the existing stat-and-unlink path remains for Windows and is documented as the residual window.

## Verification
- tests/formal/test_index_store_crash.py: crash-at-k harness over every write primitive (raise and torn variants); asserts I1-I5.
- tests/formal/test_index_store_barriers.py: subprocess barrier tests at the known windows (update read-modify-write × create; rebuild × create; renumber × create; stale-break unlink × second acquirer; parallel verify × generate-tests create); asserts I1-I4 and I6.
- A ten-line assertion in the harness parses this section's invariant names and requires a `test_I<n>_*` function for each.
- tests/test_single_index_writer.py: only the shared primitive may write the index, state, PREV, baseline or impact-log files.
- tests/formal/test_index_store_model_traces.py (UT-132): replays of the two traces the TLA+ model found (M1 create after a crashed renumber, fixed as DEF-013; M2 theirs-resolved index after a hand delete, DEF-014 recorded as an environment assumption below).

## Assumptions
POSIX rename and O_EXCL semantics on the working file system; a single machine per working tree; git merges may leave conflict markers in `_index.yaml` but not in artifact files. An `_index.yaml` merge conflict is resolved by running `specflow rebuild-index` on the conflicted file, never by taking one side (`--theirs`/`--ours`); an artifact file deleted by hand is followed by `rebuild-index` so its id enters the quarantine. Outside these assumptions an id erased from every working-tree record can be reallocated (DEF-014, wontfix; pinned by a strict xfail in UT-132).
