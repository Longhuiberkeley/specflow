# SPIDR Coverage, Wave Validation, and Generic BP Fallback

Detailed design for decomposition completeness checks and generic best-practice fallback.

## Data Structures

```python
SPIDR_DIMENSIONS = {"spidr-spike", "spidr-path", "spidr-interface", "spidr-data", "spidr-rules"}
```

## Algorithm: SPIDR Coverage Check

`_check_spidr_coverage(artifacts) -> (blocking, warnings, details)`

1. Filter to STORY artifacts.
2. Collect all tags from all stories into a set.
3. For each dimension in SPIDR_DIMENSIONS:
   a. Check if any story has a tag starting with that dimension.
   b. If not: append warning "no stories found for SPIDR dimension '<dimension>'. Stories may be incomplete."
4. If zero stories have any `spidr-*` tag: append informational note "no SPIDR dimension tags found on any story. Consider tagging stories during plan Step 5."
5. Return (0 blocking, count of uncovered dimensions, details).

## Algorithm: Wave Cycle Detection

`_check_wave_cycles(root) -> (blocking, warnings, details)`

1. Load all STORY artifacts.
2. Extract `depends_on` links from each story's frontmatter.
3. Import `compute_waves()` from `waves.py`.
4. Call `compute_waves(stories, dependencies)`.
5. If circular dependencies detected: report each cycle as a warning with the involved story IDs.
6. Report number of waves and stories per wave (informational).
7. For stories with >3 dependencies: report warning "story <ID> has <N> dependencies, consider restructuring".
8. Return counts.

## Algorithm: Generic BP Fallback

`copy_generic_fallback(cache_path: Path, phase: str)`

1. Map phase name to bundled template file: `templates/best-practices/generic-phase-{phase}.yaml`.
2. If template exists: copy to `.specflow/cache/best-practices/generic-phase-{phase}.yaml`.
3. If template does not exist for the given phase: return error "no generic fallback for phase '<phase>'".
4. Generic BPs contain 4-6 items covering universal software engineering practices scoped to the phase (e.g., plan-arc covers "define component boundaries", "specify error handling strategy", "document external dependencies").

## Bundled Generic BP Content

Generic BPs are domain-agnostic process safety rules ("wash your hands before cooking"). They cover:

- **plan-arc**: component boundaries, error strategies, dependency documentation, interface contracts
- **plan-ddd**: data structure typing, algorithm complexity, boundary error handling, preconditions
- **plan-story**: vertical slicing, independent implementability, acceptance criteria depth, sizing heuristics

Each BP item has the same schema as LLM-generated BPs (id, title, description, evaluation, anti_pattern, pitfalls).
