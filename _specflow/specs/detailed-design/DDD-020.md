# SPIDR Coverage, Wave Validation, and Generic BP Fallback

> Rewritten 2026-10-18 against the engine as built (SPIKE-008 R1-036); earlier text described a phase-split `copy_generic_fallback()` copying `templates/best-practices/` YAML into the cache, replaced by the bundled seed catalogue in `lib/practices_seed.py` behind `specflow practices seed`.

Detailed design for decomposition completeness checks and generic best-practice fallback.

## Data Structures

```python
# commands/artifact_lint.py
SPIDR_DIMENSIONS = {"spidr-spike", "spidr-path", "spidr-interface", "spidr-data", "spidr-rules"}

# lib/practices_seed.py
@dataclass
class Practice:
    title: str
    practice: str
    rationale: str
    verification: str
    domain: str = "generic"
    tags: list[str]
    seed_id: str            # e.g. "SEED-GENERIC-01"
    applicability: Callable  # in-memory predicate
    applies_when: str
    work_products: str
```

Both checks return the standard lint-check dict: `status_icon`, `detail`, `blocking_count`, `warning_count`, `findings`.

## Algorithm: SPIDR Coverage Check

`_check_spidr_coverage(artifacts) -> dict` (check `spidr-coverage`)

1. Filter to STORY artifacts. If none: return an info result ("SPIDR coverage check skipped").
2. Collect all lowercased tags from all stories into a set.
3. For each dimension in SPIDR_DIMENSIONS (sorted):
   a. Check if any collected tag contains that dimension string.
   b. If not, and there are at least as many stories as dimensions (5): emit warning finding `spidr-coverage/dimension` — "no stories found for SPIDR dimension '<dimension>'. Stories may be incomplete."
   c. If not, and there are fewer than 5 stories (STORY-695): record an informational line only, no warning.
4. If zero stories have any `spidr-*` tag: append informational note "no SPIDR dimension tags found on any story. Consider tagging stories during plan Step 5."
5. Return 0 blocking and the count of warned dimensions.

## Algorithm: Wave Cycle Detection

`_check_wave_cycles(artifacts, root) -> dict` (check `wave-cycles`)

1. Filter to STORY artifacts. If none: return an info result ("wave cycle check skipped").
2. Call `compute_waves(stories)` from `lib/waves.py`; it builds the dependency graph from `derives_from` / `depends_on` links whose target is another story and runs Kahn's algorithm.
3. If it reports a cycle (`ok: False`): emit one warning finding `wave-cycles/cycle` naming the cycle's story IDs.
4. Otherwise report the number of waves and the stories in each wave (informational; condensed unless `--verbose`).
5. For draft or approved stories only, count `derives_from` / `depends_on` links to other stories; at 4 or more, emit warning `wave-cycles/fan-in` — "<ID> has <N> dependencies, consider restructuring". Implemented and verified stories are skipped because their dependency set is historical record.
6. Return 0 blocking and the warning count.

## Algorithm: Generic BP Fallback

`specflow practices seed [--create] [--verbose]` (`commands/practices.py`; `specflow handbook generate` is a deprecated alias that delegates here)

1. `generate_handbook(root)` reads `project.domain` from `.specflow/config.yaml` via `config.get_domain`.
2. `get_practices(domain)` returns that domain's entries from `DOMAIN_PRACTICES` first, then the `GENERIC_PRACTICES`; an unknown or empty domain yields only the generic set. No API key, cache path or per-phase file is involved.
3. Without `--create`: print the title index (full bodies with `--verbose`).
4. With `--create`: create one draft BP artifact per practice via `specflow create`, stamping `provenance=bundled`, `source=<seed_id>` and `applicability` (`{"always": true}` for generic, `{"domains": [<domain>]}` otherwise). A human approves each BP; seeding only drafts it.

## Bundled Generic BP Content

Generic BPs are domain-agnostic process safety rules ("wash your hands before cooking"). The catalogue holds 6 generic practices (`SEED-GENERIC-01`..`06`):

- Separation of Concerns
- Interface Contracts First
- Testability by Design
- Error Handling at Boundaries
- Observability Built-in
- Vertical Slice Stories

plus 3 practices for each of 8 domains (web-app, cli-tool, api-service, data-pipeline, embedded, ml, quant, library).

Each practice renders the canonical five-section anatomy (Practice / Applies when / Work products / Verification / Rationale) via `Practice.to_body()`, the same anatomy every BP artifact carries (ARCH-035).
