# Convention Evaluation Logic

## Function

The convention evaluation logic validates that artifacts conform to SpecFlow's writing and structural conventions beyond basic schema compliance. It checks for EARS-pattern acceptance criteria in REQ artifacts, flags passive voice and ambiguous words in normative body text, detects compound "shall" statements that should be split, validates that DDD artifacts contain required design headers (Function, Algorithm, Data Structure, etc.), and verifies body length minimums. These checks are invoked by `specflow artifact-lint` and produce warnings rather than blocking errors.

## Algorithm

Each convention check is an independent function that takes an artifact and returns a list of warning strings. The EARS check scans for patterns like "When <trigger>, the system shall <response>" using regex matching. The ambiguity check maintains a dictionary of flagged words ("should", "may", "typically", "generally", "approximately") and reports line numbers where they appear. The body-length check counts whitespace-delimited words in the artifact body and compares against type-specific minimums (100 words for DDD, 50 for ARCH, 30 for REQ). The design-header check scans markdown headings for the presence of at least one keyword from the set {Function, Data Structure, Algorithm, Error Handling, Invariant, Precondition, Signature, Implementation}.

## Error Handling

Convention checks are non-blocking — they append warnings to the lint output without setting exit code to 1. If a check function raises an exception (e.g., encoding error reading the body), the exception is caught, and a generic warning is emitted: "Convention check failed for {artifact_id}: {error}". This ensures that one broken artifact does not prevent lint from completing its scan of the remaining corpus.
