# Test Engine DDD

## Function

The test engine provides the pytest-based test infrastructure for SpecFlow itself. It manages test discovery, fixture setup, and test execution for the project's own unit tests, integration tests, and qualification tests. The engine ensures that all SpecFlow library modules and command handlers have corresponding test coverage, and it integrates with the CI pipeline to gate merges on test pass rates.

## Algorithm

Test discovery follows pytest's standard collection protocol: tests live under `tests/` with files named `test_*.py`. Each test module imports directly from `specflow.lib` or `specflow.commands` and exercises functions with controlled inputs. Fixtures in `conftest.py` provide temporary directory roots with pre-scaffolded `.specflow/` structures, allowing tests to run against isolated filesystem state without touching the real project. The engine runs all tests via `pytest tests/` and reports pass/fail counts, which are captured as baselines before and after implementation changes.

## Implementation

The test suite is organized into unit tests (testing individual library functions in isolation), integration tests (testing command-level workflows end-to-end with real filesystem operations), and qualification tests (verifying that CLI entry points produce expected exit codes and output). Test artifacts (UT, IT, QT) in `_specflow/specs/` serve as the specification layer — each test file traces back to a DDD, ARCH, or REQ via `verified_by` links. The `pytest` configuration in `pyproject.toml` sets the test root, markers, and default options.
