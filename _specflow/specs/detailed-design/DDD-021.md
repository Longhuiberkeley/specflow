# Discovery Persistence and Plan Domain Handoff

Detailed design for skill instruction changes that persist discovery context and pass it to the planning phase.

## Algorithm: Challenge Result Persistence

During discover Step 5, for each significant challenge result:

1. **Dropped requirement**: Create DEC artifact with title "Dropped: <REQ summary>", status approved, body explaining the rationale for dropping. Link to the parent discussion context.

2. **Assumption surfaced**: Create DEC artifact with title "Assumption: <assumption text>", status draft. Body contains the assumption, what happens if wrong, and what validates it.

3. **Risk identified**: Create DEC artifact with title "Risk: <risk text>", status draft. Body contains the risk, likelihood, impact, and mitigation.

All DEC artifacts are created via `specflow create --type decision --title "<title>" --status draft`. The plan skill loads these in Step 2 via `specflow status` or by reading the decisions directory.

## Algorithm: Inter-REQ Dependency Prompting

During discover Step 4 (Requirements Summary):

1. After presenting the numbered summary, add: "Do any of these requirements depend on others being implemented first? For example, 'user authentication' might need to be done before 'password reset'."
2. For each dependency the user identifies: run `specflow update <dependent-REQ> --links "[{target: <prerequisite-REQ>, role: derives_from}]"`.
3. The plan skill can then use these dependency links to influence story wave ordering.

## Algorithm: Domain Context Pass-Through

Plan skill Step 2 reads domain context:

1. Read `.specflow/config.yaml` field `project.domain` (set during discover via `specflow domain set`).
2. Read `project.domain_tags` list.
3. If domain is set: prefix the Step 2 summary with "This is a <domain> project with focus on <tags>. Domain-specific decomposition considerations apply."
4. Load any DEC artifacts created during discover for context.

## Algorithm: Handoff Message Improvement

Discover Step 7 exit message template:

``\'
Created: REQ-<ids>

**Next steps:**
1. Review the requirements above.
2. Approve them: `specflow update REQ-<id> --status approved` (repeat for each)
3. Run `/specflow-plan` to decompose into architecture and stories.

Requirements are currently in **draft** status and must be approved before planning.
``\'

## Implementation Files

- `.claude/skills/specflow-plan/SKILL.md` — Step 2 instruction update for domain reading
