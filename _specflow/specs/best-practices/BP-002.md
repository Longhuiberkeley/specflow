# Every approval gate must present a functional description and key decisions walkthrough

## Practice
Every approval gate must include two blocks before the Action Options: a short functional description (what this does — purpose, in-scope, out-of-scope, flow for multi-part changes) and a key decisions walkthrough (what was chosen, the alternative, the tradeoff, what validates it). The gate becomes an approve-or-improve loop, not a binary yes/no.

## Rationale
The agent often presents a summary of what was created/changed (artifact IDs, field values) but the human needs to understand the behavior and the key decisions before they can meaningfully approve. A functional description in plain terms (the ML problem-set framing) gives the human the context to evaluate. The decisions walkthrough surfaces the 2-3 choices that actually determine whether the proposal is right, so the human engages decision-by-decision rather than rubber-stamping a conclusion.

## Verification
The approval-presentation.md shared format includes both blocks (§2 and §5). Every skill gate step references them. Tier 0 trims to a one-liner + one decision but still presents functionally, not abstractly.
