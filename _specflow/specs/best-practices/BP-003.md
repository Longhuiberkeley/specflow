# Every code change traces to a STORY or REQ

## Practice
Every code change (source, test, config) must trace to at least one STORY, which itself traces to a REQ/ARCH/DDD. No orphan work. Use the lean path (Step 1L) for trivial fixes, but it still records a STORY.

## Rationale
Untraced code is invisible to the spec graph: it bypasses traceability, suspect propagation, and impact review, and rots faster because no requirement explains it. The two-axis model (spec ↔ work) only holds if every work item links back to a spec.

## Verification
`specflow artifact-lint` reports zero orphan code for the change; `specflow rtm --gaps` shows the changed files under a STORY→REQ row; the commit message or PR references the STORY-NNN.
