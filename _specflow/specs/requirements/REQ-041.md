# Ops RUN lifecycle: reversible pause

## Rationale
The ops pack's run.yaml has the same irreversibility bug the autoresearch COMP schema had: paused: [live] with no path back, so pausing a RUN strands it — the only exit is retirement. The transition-map mechanism to fix this (and its test pattern) shipped with STORY-652; the ops case is strictly simpler because deployed is the sole creation root and live already carries a predecessor, so no initial_statuses key is required.

## Acceptance Criteria

1. paused → live is a legal RUN transition (live: [deployed, paused]); deployed remains the sole creation root; retired stays terminal.
2. Every transition into live remains user-gated per the ops skill doctrine — including resuming a paused RUN; the schema change grants legality, not authority.
3. The ops skill's RUN status line reflects reversibility without weakening the frozen-at-deploy doctrine.
4. Tests pin the map and both directions: `paused → live` is accepted; `retired → live` and `deployed → paused` are rejected.
