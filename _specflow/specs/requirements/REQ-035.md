# Enhanced autoresearch logging, objectives, and domain-aware checks

The autoresearch pack **shall** be enhanced to support:

1. Rich, structured experiment logging (hyperparameters, model origin, sweep results, diversity metrics, failure analysis)
2. Multi-objective competition support beyond single-best-metric (family of good, Pareto front)
3. Pre-check and post-check pipelines for each experiment iteration
4. Domain-aware auxiliary metric recommendations and lint warnings
5. Dynamic, goal-oriented loop termination suggestions
6. Noise characterization persistence on competition artifacts

## Acceptance criteria

### Schema extensions

- `competition.yaml` gains `objective_type`, `success_criteria`, `domain`, `pre_check_command`, `post_check_command`, `noise_characterization`, `goals`
- `experiment.yaml` gains `parameters`, `model_origin`, `sweep_results`, `checks`, `baseline_note`, `diversity_metrics`, `failure_analysis`
- `loop.yaml` gains `goal`, `required_findings`, `termination_suggestions`
- `finding.yaml` gains `deployability`, `safety_assessment`, `applies_to_domain`

### Protocol updates

- `autonomous-loop-protocol.md` documents Phase 0.5 (pre-check), Phase 6.5 (post-check), updated Phase 7 logging requirements, and dynamic termination using `termination_suggestions`
- `competition-setup-protocol.md` documents `goals`, noise characterization, unified runner pattern, and domain-specific auxiliary metric recommendations
- `explore-exploit-protocol.md` documents `family_of_good` mode behavior using `diversity_metrics` to prefer uncorrelated keeps
- `finding-generation-protocol.md` integrates `failure_analysis` from discarded EXPTs into `what_failed` synthesis

### CLI and deterministic enforcement

- `specflow create` and `specflow update` accept a repeatable, JSON-aware `--set KEY=VALUE` flag that writes arbitrary frontmatter via `create_artifact`/`update_artifact`. This is the mechanism the autoresearch protocols use to set EXPT/COMP/LOOP/FIND fields — without it the documented loop cannot run from the CLI
- `specflow autoresearch review` warns when: completed LOOP has zero FINDs, kept EXPT lacks `parameters`, domain-recommended auxiliary metrics are missing, discarded EXPT lacks `failure_analysis`
- `specflow autoresearch leaderboard` supports `--group-by model_origin` and `--show-family` for swarm views (flags registered in argparse)
- `specflow artifact-lint` gains `_check_autoresearch_logging` that warns when domain-recommended fields are missing on kept EXPTs

### Goal-driven research quality

- `experiment.yaml` gains `hypothesis` and `hypothesis_outcome`; Phase 2 ideation states a goal-driven hypothesis before each change and Phase 6 records whether it held (supported / not_supported / inconclusive)
- `finding-generation-protocol.md` reframes negative results as falsified / conditional / sensitive / inconclusive rather than forcing "definitively falsified" (parameter/noise sensitivity is a robustness statement, not a verdict)
- Pre/post-checks are documented as derived from `goals`/`success_criteria`; the post-check validates deploy-fit, not just a re-measured metric
- `competition-setup-protocol.md` adds a metric-vs-intent reflection so a thin single metric is caught at setup time

### Tests

- `tests/test_autoresearch_pack.py` covers all new schema fields, pre/post check lifecycle, lint warnings for missing domain metrics, and FIND enforcement on completed LOOPs
