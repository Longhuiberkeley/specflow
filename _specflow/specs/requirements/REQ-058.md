# Verification evidence is bound to what it checked: declared-exit semantics, oracle and statement pinning, formal-evidence hygiene

## Rationale
A verified test is only evidence if what it checked and what it ran are pinned. Today four readers disagree on what a passing run means (brief drops failing runs when verify_exit_code is unset; evidence hard-codes 0), a verify_command may name a test file that no longer exists (QT-011 cites an absent test) with no finding, and nothing records which content a run verified or which oracle produced the verdict. The same gap is what would make user-recorded formal evidence (model-checker or proof-assistant runs) meaningless.

## Acceptance Criteria

1. Given a recorded verify run, when any reader (brief, evidence, risk tier, project audit) judges it, then the run SHALL count as passing exactly when its exit code equals the declared verify_exit_code, defaulting to 0, compared through one shared helper.
2. Given a verify_command whose tokens name a repository path that does not exist, when lint runs, then a dead-oracle finding SHALL be emitted at accounting severity.
3. Given a verify run, when it is recorded, then it SHALL stamp the evaluator fingerprint (verify command plus the files it names, with pytest node ids resolved to their file) and the fp2 of each verified subject.
4. Given a verified test whose subject fp2 changed after the recorded run, when lint runs, then a verified_stale finding SHALL be emitted at accounting severity, discharged by a new run.
5. Given a verified test whose evaluator fingerprint changed after approval, when lint runs, then an approval_stale finding SHALL be emitted on the test at accounting severity, because re-running a weakened oracle passes.
6. Given a test whose verify_command names Lean or TLA+ inputs, when the formal-evidence lint runs, then it SHALL warn at accounting severity on sorry, admit, top-level axiom, native_decide, implemented_by, extern or unsafe tokens outside comments, on axioms outside the standard three, on a model configuration declaring no invariant or property, and on a passing model-checker log reporting fewer than 2 distinct states.
7. Given the formal-evidence lint, when it ships, then it SHALL be built only after the first real formal verify contract exists in an owned repository.
7a. Given the formal-evidence lint, when it ships, then it SHALL have no strict toggle.
8. Given the formal-evidence recipe reference, when it is shipped, then it SHALL stay at most 80 lines, pass the prose-to-CLI surface test, and never describe evidence as something an agent cannot game.
