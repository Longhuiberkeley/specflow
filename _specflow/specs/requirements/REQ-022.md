# Init Upgrade Safety

The system **shall** preserve existing project configuration and state when `specflow init` is re-executed on an already-initialized project.

## Acceptance Criteria

1. Given an initialized project with user-modified configuration values (domain, tags, packs, team roles), when `specflow init` is re-executed, then the system **shall** retain all user-modified values while applying any new default fields added since the previous version.
2. Given an initialized project, when `specflow init` is re-executed, then the system **shall** preserve the existing state file including phase history and timestamps.
3. Given an initialized project with pack-installed or user-added schema files, when `specflow init` is re-executed, then the system **shall** add any new framework schemas without deleting existing schema files.
4. Given an initialized project, when `specflow init --force` is executed, then the system **shall** replace configuration, state, and schemas with fresh defaults after backing up the previous files.
5. Given a newly initialized project, when init completes, then the system **shall** record the framework version in the project configuration to enable future migration detection.
6. Given a project initialized with an earlier framework version, when `specflow init` is re-executed, then the system **shall** detect the version difference and report which configuration fields have been added or changed.
