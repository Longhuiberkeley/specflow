## Rationale
A read-only sweep of every shipped skill, checklist, pack and always-on snippet found nine paths that fail or destroy data as documented (install deleting the always-on file on two hosts, adoption backfill commands that exit 1, an unparseable import command, a dead hook check, an in-process checklist that never parses, a release skill that snapshots before its gate, pack text teaching flags that do not exist, fabricated zero metrics, a CI gate that fails on pull requests) and a dozen cry-wolf sources. Nothing ties shipped prose to the CLI surface, so drift recurs.

## Acceptance Criteria

1. Given every specflow invocation in shipped templates, packs and docs (fenced and inline), when the prose-surface test runs, then each invocation SHALL parse against the real argument parser with no deprecated alias and no uv-run prefix outside the dogfood allowlist.
2. Given a create invocation in shipped prose with a non-entry status, when the prose-surface test runs, then it SHALL require a sanctioned justification and all required fields of that type.
3. Given every shipped checklist file, when the corpus test runs, then each file SHALL parse with at least 1 item.
3a. Given every automated checklist item, when the corpus test runs, then it SHALL carry a script.
3b. Given every per-artifact automated script, when the corpus test runs, then it SHALL reference its artifact argument.
4. Given a checklist file that fails to parse, when it is loaded, then the loader SHALL warn on stderr with the path and reason instead of returning no items.
5. Given every platform entry, when init with a preset is followed by refresh, then the base and pack sentinel blocks SHALL survive with 0 user files deleted beside the instruction file.
6. Given the always-on base block plus every shipped pack context snippet, when the budget test runs, then their combined word count SHALL be at most 375 words with no snippet repeating a sentence of the base block.
7. Given the documented command sequence of each pack skill and of the core lifecycle, when driven through the CLI in a temporary project, then artifact-lint, brief, and autoresearch status SHALL produce 0 warnings on the resulting healthy fixture.
8. Given shipped templates and packs, when the reference-lint test runs, then they SHALL contain no repository-internal path literals and no legacy D-numbered decision ids.
9. Given each of the nine broken paths and the cry-wolf sources recorded in the approved plan under DEC-090, when it is fixed, then a failing-then-passing test SHALL accompany the fix.
