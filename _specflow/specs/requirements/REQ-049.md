## Rationale
Projects without a formal standard (a plain web app) still need fit-for-circumstances guidance; creation doctrine is bifurcated today and the execute phase has zero BP hooks.

## Acceptance Criteria

1. Given a project with no installed standard or a practices list --scope gap, when planning, then the /specflow-practices skill SHALL support authoring draft BPs from the circumstance profile, applicability-filtered seeds, and exemplars, deliberately avoiding over-prescription.
2. Given any newly created BP, when presented, then it SHALL be born draft, passing practices validate before presentation, with the exact specflow update approval command printed for the human.
3. Given the skill surface, when discover, plan, execute, audit, or ship run, then each SHALL surface in-scope practices, with execute consulting practices list --scope for in-scope STORYs before coding.
4. Given --sanctioned on type best-practice, when used after this requirement ships, then it SHALL be deprecated behind a one-release alias.
5. Given the orphaned bp-authoring reference, when this requirement ships, then it SHALL be deleted and re-anchored inside the skill references.
