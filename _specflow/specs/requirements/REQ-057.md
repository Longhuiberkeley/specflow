## Rationale
No on-disk format version exists (config version is stamped only on init), there is no migration framework beyond practices migrate, and the generated pre-commit hook runs whatever specflow is on PATH with no pin. Additive changes cannot be sequenced safely without a marker, and a future 2.0.0 cannot migrate without one.

## Acceptance Criteria

1. Given init or refresh, when either completes, then the config file SHALL contain an integer format_version (initially 1) while the existing version key keeps its current semantics.
2. Given an engine whose supported format_version is lower than the repository's, when any command runs, then it SHALL warn once with the exact upgrade instruction.
3. Given that same mismatch, when the pre-commit hook runs, then it SHALL refuse with the upgrade instruction rather than run stale checks.
4. Given a repository at an older format_version, when the migrate command runs, then it SHALL be idempotent, support dry-run, refuse a dirty git tree, take a baseline first, print a status delta table, and tag every synthesised historical event as backfilled.
5. Given a baseline file written by any 1.x release, when a later engine reads it, then the diff SHALL succeed with the same added, removed and changed sets as the writing engine produced.
