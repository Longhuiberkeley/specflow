# Autoresearch: evidence-sensitive reassessment, evidence/priority separation, decomposition as hypothesis

## Rationale
An external review of the autoresearch pack found its loop protocol still decides by counts: forced category rotation at 2/3 consecutive experiments, a mandatory category switch after 5 discards, and agenda exhaustion at 3 failures. Those gates conflate accounting with judgment: a low score, an exhausted budget, or a failure streak is not evidence that a research direction is dead. The protocol also conflates evidence classification with priority, mandates post-LOOP delegation to a subagent, and leaves three different "loops" (the runtime iteration cycle, the SpecFlow LOOP artifact, a project's own research cycle) ambiguous. Mission value should drive continuation; counts are accounting, not decisions. A follow-up redline tightened the reassessment predicate: evidence movement must be recent, anchored, and novel rather than inferred from outcome labels or any keep anywhere in the tail.

## Requirements
R1 Decomposition is a hypothesis: before running the baseline, the protocol records the width of plausible formulations (component / joint or tightly coupled / end-to-end where relevant), each formulation's assumptions, tradeoffs, and how it would be evaluated. The research agenda is the recorded reasoning, not a direction-count quota.
R2 One experiment tests one coherent hypothesis. Coordinated component changes are allowed when they are logged as serving that hypothesis; unrelated changes still split into separate experiments.
R3 Evidence and priority are separate fields. EXPT `hypothesis_outcome` records evidence: `supported` / `not_supported` (scoped falsification — state the tested scope) / `inconclusive` / `invalid` (invalid instrument). LOOP research-agenda entries may carry `priority` (`pursue` / `deprioritize` / `blocked` / `revisit`) and `progress` (new evidence tied to the next decision) — no priority is derived from a failure count.
R4 Reassessment is evidence-sensitive over a bounded recent window. The CLI warns (never blocks) when a sustained same-category line or a consecutive non-kept run shows no new evidence in its last three experiments; a keep older than that window never suppresses a stagnant tail. New evidence is either an EXPT `research_progress` note (`evidence_ref` anchored narrowly to that EXPT — ID exactly or with an explicit `#fragment`, recorded `commit` exactly or as a ≥7-character hex abbreviation, or a repo-relative output path logged outside the note and existing — with a distinct `finding` and a `next_decision`), or a kept status with a new best primary `metric_value` per direction (a sign-consistent finite `delta` only when no comparable metric exists; NaN/Infinity never count). Outcome labels alone (including alternating `invalid`/`inconclusive`), repeated claims or evidence refs under a new path, malformed/absent records, and repeat keeps at the incumbent best do not count. The accounting checks existence, anchoring, and novelty — never truth; the agent still reads the cited source. Forced 2/3 category rotation, the 5-discard category switch, and 3-failure agenda exhaustion are removed from the CLI and every skill reference.
R5 Continuation is mission-value driven. Low scores, budget, and failure counts are accounting, not broad kills; a formulation may be deprioritized (or B chosen) without proving A impossible. Feasibility is checked before expensive tests; negative and infeasible results are recorded as negative memory (`failure_analysis`, `lessons_learned`, FIND `what_failed`); noise floor, held-out confirmation, and multiplicity guidance (ML-08/ML-09/ML-13) stay in force.
R6 One investigator owns the loop and its deterministic log (`autoresearch log`). Independent review is optional and boundary-driven (LOOP completion with many EXPTs, cross-loop synthesis, COMP closure, FIND→REQ promotion) with a sequential fallback; the mandatory post-LOOP delegate rule is removed.
R7 No new modes or personas, and no dependency on an external orchestrator; the pack stays modeless and CLI-only for guarantees.
R8 Terminology distinguishes the runtime iteration loop, the SpecFlow research LOOP artifact, and a project's own research cycle (e.g. S1–S5), which stays project-specific. Nonmetric exploration uses SPIKE/FIND artifacts and never fabricates a score for a COMP.
R9 Instructions are concise and non-contradictory: the CLI-printed protocol, SKILL.md, and every reference agree on R1–R8; old contradictory rules are deleted rather than layered over. A prioritized agenda direction without a `progress` note is an advisory (exit code stays 0), not an exit-3 warn source.
R10 The progress record has one validated producer: `specflow autoresearch log --research-progress '<json>'` writes `{evidence_ref, finding, next_decision}` (all non-empty strings) and rejects malformed JSON or a missing field before creating anything. The schema (`experiment.yaml`), lint (malformed-shape advisory), docs, and the status consumer agree, and a `--set research_progress=` override is refused as reserved.

## Acceptance Criteria
Given a LOOP whose research agenda has two directions, when `specflow autoresearch status` runs at any budget, then no minimum-direction warning is emitted and the agenda line names the recorded directions.

Given a sustained same-category or consecutive non-kept run whose last three EXPTs each carry a distinct, anchored `research_progress` record, when `autoresearch status` runs, then no reassessment warning is emitted; given the same run with outcome labels alone, repeated claims/refs, a malformed or absent record, or repeat keeps without measured improvement, then a reassessment warning is emitted at warn level (exit 3) and never as a structural failure. A keep older than the last three experiments does not suppress the warning.

Given an agenda direction with `priority: blocked` or `priority: deprioritize`, when `status` renders open directions, then the direction is excluded, while `priority: revisit` remains open.

Given a kept EXPT with `hypothesis_outcome: invalid`, when `artifact-lint` runs, then the value is accepted as a valid evidence outcome.

Given `specflow autoresearch log --research-progress '<json>'`, when the payload is a JSON object with non-empty `evidence_ref`, `finding`, and `next_decision`, then the field is recorded on the EXPT; when it is malformed, then the command exits 1 and creates no EXPT.

Given the skill references and the CLI-printed protocol, when a reader searches for count-driven continuation rules, then no rule mandates category rotation by streak length, a category switch after five discards, agenda exhaustion after three failures, or post-LOOP delegation.
