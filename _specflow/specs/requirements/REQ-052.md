## Rationale
SpecFlow's semantics are declared in about ten duplicated Python registries and eight independent traceability implementations that drift apart when maintained independently. One declaration, derived everywhere, with a mechanical guard, removes the class of defect.

## Acceptance Criteria

1. Given the packaged core ontology file, when the registry is compiled, then every artifact type, kind, lifecycle, link role and role-target row SHALL be derivable from it alone.
2. Given the derived tables, when the equivalence test runs before the legacy constants are deleted, then the derived tables SHALL equal the previously hard-coded constants.
3. Given any module outside the core package, when the architecture test runs, then a type, prefix or link-role string literal not on the shrink-only allowlist SHALL fail the test.
4. Given the rules check command, when it runs on a project, then an unreachable lifecycle, a lifecycle without an entry state, a role with zero or two orientations, a matrix row naming an undeclared type, or a pack overlay redefining a core role SHALL produce a non-zero exit.
5. Given a consumer schema or pack schema that is malformed or conflicts with the core ontology, when it is loaded, then the loader SHALL fail with the file path and reason instead of silently skipping the type.
6. Given each artifact type, when its kind is resolved, then the result SHALL be exactly one of claim, work, evidence or judgment as declared in the ontology.
7. Given the orphan, coverage-denominator and suspect-cascade rules, when they classify an artifact, then they SHALL consult the resolved kind rather than a type literal.
