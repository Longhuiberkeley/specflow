## Rationale
Lint and audit findings are rendered strings re-parsed for identity, and the exit code depends on hidden state (run-count history, first-run seeding, wall clock, silently swallowed lens exceptions, a cache key that omits non-artifact inputs). Determinism is a precondition for any compliance argument and for agent trust.

## Acceptance Criteria

1. Given an unchanged repository, when artifact-lint or project-audit runs 2 consecutive times, then both runs SHALL produce identical findings and identical exit codes.
2. Given an artifact-lint run, when it completes, then it SHALL have performed 0 writes to the .specflow state directory.
3. Given every check and lens, when a finding is produced, then it SHALL be a typed record carrying rule_id, subject ids, severity, class (escalating or accounting) and structured args.
4. Given an existing rule id, when its finding is rendered, then the text SHALL be byte-identical to the pre-change output.
5. Given the project-audit findings cache, when any input read by a cross-cutting lens changes (standards directory, baselines, docs tree, source-tree signature), then the cache key SHALL change.
6. Given a lens or loader that raises an exception, when audit or lint runs, then a lens-error or schema-error finding SHALL be emitted at blocking severity in place of the swallowed failure.
7. Given a persisting warning, when escalation is decided, then it SHALL be decided against a committed findings-baseline file keyed by rule_id and subject rather than by consecutive-run counters.
8. Given the findings-baseline file, when it is modified, then the only writer SHALL be the findings-baseline update command.
9. Given a time- or environment-dependent check (spike staleness, source drift, git-derived independence), when it runs, then its environment inputs SHALL be explicit facts recorded in the output (an as-of date, an explicit source-drift seed command) rather than implicit reads.
