# Eliminate false-confidence signals (v1.13 cycle)

Two independent false-confidence signals undermined the release gate during the
v1.12 dogfood cycle: (1) the `verified` status was an assertion, not
machine-checked evidence — nothing recorded that a verification command actually
ran and passed; (2) deterministic audit warnings that should have been advisory
were driving the gate's exit code (cry-wolf), so real structural findings were
drowned out. v1.13 eliminates both.

## Scope

1. **Verification contracts.** UT/IT/QT/STORY may declare a `verify_command`
   (plus `verify_exit_code`, `verify_evidence`). `specflow verify` runs the
   declared command and records the result (`verify_run_at`,
   `verify_run_exit_code`, `verify_run_evidence`) so `verified` is traced, not
   asserted.
2. **Accounting lenses.** `specflow project-audit` gains lenses that surface
   verification-evidence gaps and verify-command divergence as **warnings**,
   feeding brief/router visibility without becoming blocking findings.
3. **Entry-point sync.** The verify step is wired into the execute skill, the
   CLI reference, the lifecycle flowchart (mermaid + ASCII), the README feature
   surface, and the `brief --next` router as one advisory line.

## Acceptance criteria

- `specflow verify <ID> | --all | --type T | --dry-run | --evidence-file PATH`
  is a working command that executes a declared `verify_command` and writes
  `verify_run_at` + `verify_run_exit_code` (+ `verify_run_evidence`) onto the
  artifact's frontmatter.
- A failing `verify_command` is **recorded** truthfully (real exit code captured)
  and **never blocks** a commit, a status transition, or a release — the
  accounting-not-policing invariant, machine-enforced.
- Verified artifacts carry machine-checkable `verify_run_*` evidence when a
  `verify_command` is declared (artifacts with no contract are unaffected and
  not penalized).
- Accounting warnings about missing/divergent verification evidence **never**
  drive the `specflow project-audit` / release-gate exit code to 2 — only
  structural findings do.
- `specflow brief --next` surfaces a verify-evidence gap as exactly one
  deterministic, advisory line (frontmatter query: declared `verify_command`
  with no `verify_run_at`, or `verify_run_exit_code` != declared
  `verify_exit_code`); never blocking, silent for projects that use no contracts.
- The `/specflow-execute` skill names `specflow verify <ID>` (or `--all`) as a
  deterministic step before transitioning test/story artifacts to `verified`,
  mirroring how it already invokes `specflow artifact-lint`.
- `docs/cli-reference.md`, `docs/lifecycle.md` (mermaid AND ASCII), and the
  README feature table each reference `specflow verify` / verification contracts
  consistently.
- The shipped skill template and its live `.claude/skills/` mirror stay in
  parity (a new `references/verification-contracts.md` documents field meanings,
  recorded run fields, and the never-blocking invariant).

## Out of scope

- No new artifact types and no new link roles (D-18 frozen vocabulary respected).
- No external LLM calls — `verify_command` is the user's own shell command; the
  engine only executes and records.
- Verification contracts are opt-in; existing V-model `verified_by` links remain
  the structural verification proof.
