# Craft-discipline and evidence-contract extensions in lifecycle skills

## Context

DEC-102 recorded that SpecFlow governs when rigour happens but is thin on the in-flight craft layer. The 2026-10 landscape survey confirmed it: superpowers, Ralph, GSD, pro-workflow, metaswarm and oh-my-claudecode each encode a small set of coding-discipline rules that the execute skill does not state; trailofbits/skills, flow-next and GSD encode verdict vocabularies and "rationalizations to reject" that the evidence-label contract (REQ-066) does not yet cover; compound-engineering and superpowers scale ceremony by risk, which the discover readiness reference does not state; Anthropic's feature-dev plugin writes competing option briefs before committing to a design. Adversarial review rejected six separate reference files in favour of one shared craft reference plus small additions to existing files, so the always-on context budget is unchanged (SKILL.md routers stay under the DEC-083 budgets; knowledge loads on demand from references/). Sources are MIT except trailofbits/skills (CC-BY-SA), whose ideas are re-expressed in SpecFlow's own words; nothing is taken from Commons-Clause task-master.

## Obligations

- OBL-1: The execute skill MUST point to one shared craft-discipline reference (RFC 2119) covering: search before writing and reuse before adding; the shortest diff that satisfies the acceptance criteria; never weakening validation, data-loss or security handling to make a check pass; no stubs or placeholder implementations; writing the failing test before the step-3 baseline so the step-6 delta shows it as fixed, and treating a test that passes immediately as suspect; counting pass/fail/skip in the baseline and reporting a STORY-caused skip increase as caused; stopping after two failed fixes on the same check and naming the shared assumption; spilling verbose tool output to a file and reporting exit code plus tail.
- OBL-2: The evidence-label reference MUST define verdict states (`not-verified (reason)`, per-AC VERIFIED / PARTIAL / MISSING, regression wording) and a closing "Skipped or substituted:" line; MUST define untrusted-source handling for ingestion skills (unverifiable content maps to `guess`); and MUST carry a short table of rationalizations to reject, stated in SpecFlow terms. The file MUST stay within a pinned line budget because three lifecycle routers load it.
- OBL-3: The artifact-review severity reference MUST state that an agent or lens `blocking` finding needs `measured` evidence, with `inferred` capped at warning and `guess` at info.
- OBL-4: The discover readiness reference MUST state that an irreversible change or large blast radius forces the full path regardless of exchange count.
- OBL-5: The execute skill MUST state that a problem found outside the in-scope STORY becomes a DEF or follow-up rather than a silent fix, with the repo's own checks failing on changed files as the one exception; the plan skill MUST state that a real structural choice gets two or three option briefs before an ARCH is written.
- OBL-6: Every normative sentence added under this REQ MUST be pinned in `tests/test_core_skill_text.py` with DEC provenance, and the live `.claude/skills` and shipped template trees MUST stay byte-identical.

## Acceptance Criteria

1. Given `specflow-execute/SKILL.md`, when read, then it lists `references/craft-discipline.md` exactly once and stays within its 120-line budget.
2. Given `craft-discipline.md`, when `tests/test_core_skill_text.py` runs, then each OBL-1 rule is present as a pinned RFC 2119 sentence.
3. Given `evidence-labels.md`, when the pin tests run, then the verdict-state sentences, the untrusted-source sentences and the rationalization table header are present, and the file is at or under its pinned line budget.
4. Given `severity-levels.md`, `readiness-assessment.md`, `specflow-execute/SKILL.md` and `specflow-plan/SKILL.md`, when the pin tests run, then the OBL-3, OBL-4 and OBL-5 sentences are present exactly once each.
5. Given the two skill trees, when `diff -rq .claude/skills src/specflow/templates/skills/shared` runs, then it prints nothing.
6. Given `verification-contracts.md`, when read, then the recorded-output field is named as the engine writes it, not `verify_run_evidence`.
