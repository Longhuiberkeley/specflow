# Frame a fuzzy idea inside /specflow-discover with a go / clarify / kill verdict

## Context

Users often arrive with a fuzzy idea ("some kind of dashboard for the ops team?") rather than a requirement. Today `/specflow-discover` either interrogates or declines, and docs/comparison.md tells the user to go elsewhere first. DEC-104 folds a persona-free framing step into discover as the zero end of its readiness curve.

## Obligations

- OBL-1: `/specflow-discover` MUST frame an ask that satisfies at most one required readiness dimension before eliciting requirements, following `references/framing.md`, and MUST NOT frame an ask that already meets the readiness threshold.
- OBL-2: Framing MUST ask at most five questions, one per message, each with a recommended answer, and MUST ground in the repository (`specflow brief`, `list`, `trace`, README, touched code) before asking.
- OBL-3: Framing MUST record a premise ledger the user accepts or rejects explicitly, MUST offer two or three option briefs plus do-nothing, and MUST hard-stop for the user's choice before any REQ or code.
- OBL-4: Framing MUST end in exactly one verdict — go, clarify or kill — recorded as a DEC tagged `framing` (go/kill approved with the user's quoted verdict, clarify draft), and a go verdict MUST continue at discover step 2 with the lean/full exchange count restarted.
- OBL-5: REQs born from a go verdict MUST link `guided_by` to the framing DEC; a kill MUST be an approved `Dropped:` DEC.
- OBL-7: A DEC tagged `framing` MUST NOT trip the `links/orphan` lint row, because a kill or clarify ruling in a project with no related artifact yet is complete in itself; every other rule applies unchanged.
- OBL-6: The discover description, the `/specflow-start` router, README, docs/comparison.md and docs/lifecycle.md MUST state the narrowed positioning; the discover router MUST stay within its 120-line budget and both skill trees MUST stay byte-identical; every new normative sentence MUST be pinned with DEC-104 provenance.

## Acceptance Criteria

1. Given an opening message such as "I want a better app", when discover starts, then framing runs: the first reply contains an opt-out line and exactly one question with a recommended answer.
2. Given "Add a dark-mode toggle to settings for end users, iOS and Android, by Q2", when discover starts, then framing does not run and the lean path proceeds.
3. Given a framing session, when the fifth question has been asked, then no further question is asked and remaining gaps appear as premises.
4. Given a premise the user did not answer, when a verdict is proposed, then the verdict is clarify or kill, never go.
5. Given a go verdict, when discover continues, then a DEC tagged `framing` exists with status approved, the exchange count restarts, and each REQ created afterwards links `guided_by` to it (`specflow trace <DEC-ID>` shows the REQs downstream).
6. Given a kill verdict, when the same idea is raised again, then conflict-check quotes the approved `Dropped:` DEC before any question.
7. Given the shipped text, when `tests/test_core_skill_text.py` and `tests/test_reference_lint.py` run, then the framing sentences are pinned, discover is ≤120 lines, and `diff -rq .claude/skills src/specflow/templates/skills/shared` is empty.
8. Given docs/comparison.md, README.md, docs/lifecycle.md and docs/commands.md, when read, then none says SpecFlow has no ideation step; each states the narrowed positioning.
9. Given an approved DEC tagged `framing` with no links, when `artifact-lint` runs, then no `links/orphan` finding names it; given the same DEC without the tag, then the row fires as before.
