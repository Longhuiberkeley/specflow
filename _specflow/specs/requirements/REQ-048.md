## Rationale
Guidance must surface because circumstances and lifecycle moment match, not because a skill happens to call a list command.

## Acceptance Criteria

1. Given a project, when specflow practices profile runs, then a zero-token circumstance vector SHALL be computed from the artifact graph and filesystem and persisted in a CLI-managed .specflow/practice-profile.yaml that is never hand-edited.
2. Given the profile label, when rendered, then it SHALL be an advisory guidance weight, asserted by test to never influence exit codes.
3. Given applicability matching, when practices load, then circumstance and lifecycle-moment predicates SHALL apply before tag fallback.
4. Given specflow brief, when guidance exists, then in-scope versus dormant approved BPs SHALL be reported.
