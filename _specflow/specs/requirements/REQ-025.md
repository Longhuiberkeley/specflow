# Reverse Impact Analysis

The system **shall** detect source code and data product changes via git diff and flag spec artifacts that govern those files as suspect, closing the traceability loop from code back to specification.

## Acceptance Criteria

1. Given an artifact with `output_files` listing `src/specflow/lib/impact.py`, when that file is modified in a git commit, then the system **shall** flag the artifact as suspect during impact analysis.
2. Given a commit that modifies multiple files governed by different artifacts, when impact analysis runs, then each affected artifact **shall** be flagged independently.
3. Given a commit that modifies files not listed in any artifact's `output_files`, when impact analysis runs, then no false suspect flags **shall** be produced.
4. Given a glob pattern in `output_files` (e.g., `output/YY_MM_DD_*.json`), when a matching file is modified, then the governing artifact **shall** be flagged as suspect.
5. Given `specflow change-impact` execution after a commit, then the report **shall** include a section listing source file changes and their associated spec artifacts.
