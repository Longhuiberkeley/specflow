## Rationale
Process knowledge dies in write-only LOOP fields today (loop.yaml lesson fields have no CLI consumer) and the promised FIND-to-BP loop exists only as prose; the flywheel must close deterministically.

## Acceptance Criteria

1. Given a confirmed FIND, PREV, or LOOP lessons source, when specflow practices promote --from runs, then a BP draft SHALL be created by a deterministic graph transform (source exists; idempotent refusal when a BP already cites it; derives_from edge written; provenance learned; confidence low; applicability from the COMP domain; verification method copied from the experiment evaluation protocol).
2. Given LOOP lesson themes recurring in two or more LOOPs of distinct COMPs, when suggest-finds --process runs, then recurrence candidates with LOOP ids and quotations SHALL be rendered, with the model authoring the draft behind one human gate.
3. Given LOOP setup with in-scope BPs, when the LOOP starts, then consulted BP ids SHALL be recorded (mirroring checklists_applied shape) so EXPT -> FIND -> BP -> next-LOOP consumption is queryable by trace and review.
4. Given a learned BP, when created, then its default strength SHALL be informal or recommended so mid-LOOP tailoring ceremony is never forced.
5. Given a second structurally independent confirmed FIND citing a BP, when confidence recompute runs, then the CLI SHALL propose the raise for human application only, with no count-based auto-promotion.
