# Autoresearch methodology context: thin pack checklists, rolling-evaluation recipe

## Rationale
DEC-078 (checklists teach SpecFlow mapping, not domain methodology) has not been applied to the autoresearch pack's own references/domain-research-checklists.md, which still pre-prompts subfield methodology menus that modern models carry natively and that encode maintainer bias. Separately, the operator-ratified v1.15.0 rolling-evaluation/split-R&D design (ROADMAP) has no shipped artifact: no recipe reference, no DEC recording the COMP churn rule, and no window_end schema registration.

## Acceptance Criteria
1. domain-research-checklists.md is rewritten thin — concept-to-artifact mapping plus universal open questions — preserving the five domain keys (quant, tabular_ml, vision, nlp, generic) used by protocol call sites.
2. references/rolling-evaluation.md ships: fixed train/val/test vs rolling/walk-forward as a first-class design choice, split methodology as a researchable object (EXPTs over split configs via the validation change_category), retrain-window sizing and historical→live transition as named research tracks, the COMP churn rule, and window_end advance as successor-COMP creation.
3. competition.yaml registers window_end in optional_fields, pinned by a locking test.
4. The privacy denylist gate stays green on every edited file; no personal-context fingerprints.
