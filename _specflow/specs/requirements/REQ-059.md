# Transcript-mined agent ergonomics — wave 3

## Context

Mining ~1,785 chat-transcript files (dogfood repo plus five consumer projects, 2026-09-18..2026-10-07) showed that lifecycle skills are almost never invoked (0-3 Skill calls per corpus) and ~80% of CLI calls come from subagents, so CLI help and error text is the de facto interface. Recurring rituals: `</dev/null` on 134 of 390 calls (stdin EOF warning), ANSI stripping, blanket `--skip-dedup-check --force`, create/update help re-read 42-50 times per repo, `cd _specflow` root failures, `artifact-lint <ID>` usage dumps, and ~880 hand-edits of `_specflow/`. Successor to REQ-064.

## Constraints

- No new blocking gates, no mode toggles, no cry-wolf signals; exit codes unchanged unless stated.
- Zero external LLM calls; host-agnostic; bare `specflow` in shipped prose.
- D-18 link vocabulary stays frozen.

## Acceptance Criteria

- [ ] AC1: `specflow update <ID> --status X </dev/null` and with `stdin=DEVNULL` print no "Stdin data ignored" warning, while a real piped body combined with flags still warns.
- [ ] AC2: With `NO_COLOR` set or stdout not a TTY, no command emits ANSI escape sequences; `FORCE_COLOR` restores them.
- [ ] AC3: `specflow create` in non-interactive mode prints duplicate candidates and proceeds with exit 0; type aliases (`REQ`, `req`) are normalised before the dedup search.
- [ ] AC4: Any `specflow` command run from a subdirectory of a project (e.g. `_specflow/work`) resolves the nearest ancestor containing `.specflow/`; `init` keeps using the cwd.
- [ ] AC5: A shell-collapsed token such as `"--add-link X:role"` yields a quoting hint, an unknown `--set` field names `specflow schema <type>`, and `artifact-lint <ID>` returns a one-line scope hint instead of the usage dump.
- [ ] AC6: `--help` of every command that never writes under `_specflow/` or `.specflow/` carries a "(read-only)" marker.
- [ ] AC7: `update --set` refuses `id`, `type` and `created`, and prints "No changes to apply" instead of a success mark when nothing changed.
- [ ] AC8: Delegation guidance in the start, execute and plan skills tells an orchestrator what to pass to a subagent (skill name, `brief --next` output, exact IDs) and how to read references without `| head`.
