# Evidence-labeled claims in lifecycle skill output

## Context

REQ-060 made the next-step digest deterministic, but the reply around it is still free prose. An agent asserting "all tests pass" without running them reads identically to one that measured it, and a cited artifact ID or file:line the agent never read this session is indistinguishable from a verified one. pstack's poteto-mode "Writing the reply" contract and its unslop skill solve exactly this at the prose layer. Derived from poteto/pstack and michael-denyer/pstack-claude (MIT).

## Obligation

- OBL-1 (RFC 2119): Lifecycle skill replies MUST label every claim measured, inferred, or guess in the same sentence as the claim, and MUST NOT cite artifact IDs or file:line references the agent did not produce or read in the current session.

## Acceptance Criteria

1. Given a lifecycle skill reply that states a claim, when the sentence is written, then it carries its evidence or its label — measured, inferred, or guess — in that same sentence.
2. Given an artifact ID or file:line the agent did not produce or read this session, when the reply is composed, then it is not cited; IDs are verified with `specflow trace` or `specflow list` before citing.
3. Given a deterministic CLI check exists for a claim (artifact-lint, verify, cascade-status), when a lifecycle skill would report its expected result, then the skill instructs the agent to run the check instead of describing it.
4. Given the normative sentences ship in lifecycle skills, when the test suite runs, then each new sentence is pinned by phrase in tests/test_core_skill_text.py with DEC provenance comments.
