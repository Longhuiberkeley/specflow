## Rationale
Bring-your-own-standard must become load-bearing alignment (SOC2, ASPICE, ISO-family adoption): clause content, generation, integrity checks, and coverage reporting.

## Acceptance Criteria
1. Given an installed standards pack, when clauses carry optional severity, strength, applicability, verification, work-products, or parent fields, then absent fields SHALL keep current defaults so existing packs stay valid.
2. Given an installed standard, when specflow practices generate --from-standard runs, then one BP per applicable clause SHALL be emitted with provenance standard and a complies_with edge, making that role load-bearing.
3. Given pack-validate on a standards pack, when it runs, then clause integrity (unique ids, id format, hierarchy preserved, vocabulary membership) SHALL be checked deterministically.
4. Given the coverage view, when specflow practices matrix runs, then practice x circumstance x (applied / dropped with rationale / gap) SHALL render with advisory ASPICE-style bands, never gated.
5. Given methodology-handbook ML entries, when this requirement ships, then they SHALL migrate to domain seeds with endgame applicability so rolling-evaluation and explore-exploit read practices list --scope instead of prose.
