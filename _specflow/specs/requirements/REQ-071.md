# Ledger bodies and test specs reflect the engine as built — wave 2 (ARCH/DDD rewrites, test-spec promotion, output_files truth)

## Problem

v1.17.7 fixed prose and added dated amendment notes, but 19 ARCH/DDD bodies still describe deleted modules, flags and flows (ARCH-001/003/004/005/007/009/010/011/014/015/016/017/018/019/020/025/027/031/035, DDD-020); 56 UT/IT/QT specs are draft although their parents are implemented or verified (practice spine UT-089..102 / IT-055..070 / QT-054..073, plus UT-153/154, IT-113/114, QT-114/115 which already carry a verify_command); IT/QT/UT bodies cite consolidated test files that no longer exist; and some verified STORYs list auto-captured output_files that other stories implement.

## Obligations

- **OBL-1 (ARCH/DDD rewrite).** Each listed ARCH/DDD body SHALL be rewritten so every component, interface, data-flow step and acceptance criterion names modules, functions, flags and behaviours that exist in the engine today, with one line recording the rewrite date and SPIKE-008 as the source; the v1.17.7 amendment notes MAY be folded into that line. No ARCH status SHALL move backwards.
- **OBL-2 (test-spec promotion).** Every draft UT/IT/QT whose parent STORY/ARCH/DDD/REQ is implemented or verified SHALL either gain a verify_command and output_files pointing at the real test(s) and be promoted draft → approved → implemented after `specflow verify` exits 0, or, when its parent is deprecated or no test exists, be moved to the legal terminal status with a one-line reason in the body.
- **OBL-3 (test citations).** UT/IT/QT bodies that cite a test file which no longer exists SHALL cite the file that now holds those tests.
- **OBL-4 (output_files truth).** A verified STORY SHALL list under output_files only files it implements; auto-captured entries that belong to another STORY SHALL be moved to that STORY or dropped, followed by `specflow fingerprint-refresh --source`.

## Acceptance criteria

- AC1: Given each listed ARCH/DDD, when its body is grepped for the stale names recorded in SPIKE-008 rows (best_practices.py, Click, uuid5, .reqifz, --direction, read_version, merge_schemas, conventions, 10 Tier-1, 14 platforms, net diff), then none remains outside the rewrite line.
- AC2: Given `specflow list --type unit-test`, `integration-test` and `qualification-test`, when run after the change, then no spec whose parent is implemented or verified is still draft, and every promoted spec carries verify_run_exit_code 0.
- AC3: Given every UT/IT/QT body, when each cited tests/*.py path is checked on disk, then it exists.
- AC4: Given the STORYs named in SPIKE-008 output_files rows, when their output_files are read, then each file is implemented by that STORY, and `specflow artifact-lint` reports no new findings.
- AC5: Given `uv run pytest tests/`, when run after the change, then it is green.
