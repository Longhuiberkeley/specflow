# Deterministic robustness signals: honest go, working-tree-aware brief, live PREV loop, placeholder and disposition lint

## Context

The 2026-10 landscape survey of 30 AI-coding skill stacks (gstack, superpowers, spec-kit, compound-engineering, GSD, flow-next, trailofbits/skills and others) was judged against SpecFlow's design philosophy. The practices that survived adversarial review and are deterministic land here as engine behaviour; prose-level practices are REQ-068. Each item below was measured in this repository at v1.17.4: `specflow go` without `--dry-run` runs `git add -A && git commit` per wave after a stub `execute_story` that always returns ok (lib/executor.py), so it reports "Completed" for stories nobody executed; `specflow brief` reads only `git log` and never the working tree, so it routed to /specflow-ship while 37 paths were uncommitted; 18 of 20 learned prevention patterns carry `applies_to.tags: []` and `lib/checklists.py match_tags` is a set intersection, so they can never be assembled; 20 verified or draft test specs still carry the generator placeholder `TODO: Define test cases`; 90 of 94 accepted CHLs have a `rationale` identical to their title because the create path fills it with the finding text and the schema has no disposition-reason slot (DEC-102 Track 4, slice A). Sources (MIT unless noted, ideas re-expressed): GSD and superpowers (honest completion, no blanket staging), humanlayer ACE and metaswarm (session handoff sees the dirty tree), compound-engineering and GSD (learnings re-enter checklists), BMAD and superpowers (placeholder grep), trailofbits/skills (CC-BY-SA; disposition reasons).

## Obligations

- OBL-1: `specflow go` MUST NOT stage or commit files. It MUST report context assembly truthfully and MUST NOT describe an unexecuted story as completed. This amends REQ-001 §6 "Auto-commit per task completion" (recorded in DEC-103).
- OBL-2: `specflow brief` MUST report the uncommitted working tree, distinguishing `_specflow/` ledger paths, source paths and `.specflow/`-only engine state, and `brief --next` MUST carry an advisory line when ledger or source paths are uncommitted. Exit codes MUST NOT change.
- OBL-3: A prevention pattern seeded on DEF closure MUST inherit matchable tags (the DEF's tags plus the tags of its `fails_to_meet` REQs, excluding release tags matching `^v\d`), and an empty result MUST be reported as inert. Existing inert patterns MUST be repairable through the CLI without hand-editing `.specflow/`.
- OBL-4: `artifact-lint` MUST warn (accounting, never blocking) when an artifact past `draft` still contains the test-spec generator placeholder, and the rule MUST match the single generator constant rather than a hand-copied string.
- OBL-5: The challenge schema MUST offer an optional `resolution` field, and `artifact-lint` MUST warn (accounting) when an `accepted` CHL carries no `resolution`.
- OBL-6: Every new lint rule id MUST ship with a negative fixture in `tests/test_lint_negative_fixtures.py` (REQ-065).

## Acceptance Criteria

1. Given a git repository with uncommitted files and approved stories, when `specflow go` runs without `--dry-run`, then no commit is created, nothing is staged, every `git status --porcelain` line outside `.specflow/` is unchanged (the engine may write its own `.specflow/state.yaml`), and the summary line reads "Context assembled" rather than "Completed".
2. Given the `go` subparser, when `specflow go --help` prints, then no `--timeout` flag is offered and `docs/cli-reference.md` matches.
3. Given modified or untracked paths under `_specflow/`, `src/` or `tests/`, when `specflow brief` runs, then a "Working tree" line names the counts per bucket, and `specflow brief --next` appends an advisory line; given only `.specflow/` changes, then neither appears.
4. Given a DEF tagged `cli` that `fails_to_meet` a REQ tagged `core`, when the DEF closes and a PREV is seeded, then the PREV's `applies_to.tags` contains both `cli` and `core` and excludes tags matching `^v\d`.
5. Given a seeded PREV whose computed tags are empty, when seeding completes, then the CLI output names the PREV as inert and prints the exact `specflow patterns update <PREV> --tags <a,b>` repair command.
6. Given `specflow patterns update PREV-NNN --tags a,b`, when it runs, then the YAML under `.specflow/checklists/learned/` carries exactly those tags and `specflow checklist-run` on an artifact tagged `a` assembles that PREV.
7. Given `specflow project-audit`, when at least one PREV has empty tags, then a `prev/inert` accounting row names it and the exit code is unaffected; given `specflow brief`, then the knowledge line reads "PREV N (M inert)".
8. Given a `verified` unit-test spec whose body still contains the generator placeholder, when `specflow artifact-lint` runs, then a `placeholder/unfilled` warning names it; given the same text inside a fenced code block, or a `draft` artifact, then no finding is emitted.
9. Given an `accepted` CHL with no `resolution` field, when `specflow artifact-lint` runs, then a `challenge/disposition-without-reason` warning names it; given `resolution` set, then none.
10. Given `tests/test_lint_negative_fixtures.py`, when it runs, then both new rule ids have fixtures and the both-directions coverage test passes.
11. Given the 20 test specs that carried the placeholder at v1.17.4, when this REQ is verified, then each lists real test cases and `artifact-lint --type placeholder` emits zero `placeholder/unfilled` findings on this repository (the rule ignores inline code and fenced blocks, so prose that quotes the placeholder, such as this REQ, does not count).
