# Autoresearch ships as an opt-in pack, not core

## Context

Autoresearch adds 4 artifact types, 4 new directories under `_specflow/specs/`, a skill, and 4 reference documents. We had two paths to ship it.

## Options considered

| Option | Pros | Cons |
|---|---|---|
| **Bundle in core SpecFlow** | Always available; simpler discovery | Pollutes `_specflow/` tree for non-research projects; couples release cadence |
| **Ship as opt-in pack** (chosen) | Clean separation; reuses existing pack mechanism; users opt in via `specflow init --with-pack autoresearch` | Requires extending pack system to install skills |

## Resolution

Autoresearch ships as a pack at `src/specflow/packs/autoresearch/`. The cost of extending the pack system to support skill installation (one new field, ~30 lines in `apply_pack`) is paid back by:

1. Future packs (compliance, defect-tracking, etc.) can ship skills the same way
2. Default SpecFlow remains lean
3. Users who don't need autoresearch never see COMP/LOOP/EXPT/FIND
