# Pack-bundled skills follow no-overwrite install policy

## Context

`apply_pack` currently preserves user edits for schemas, checklists, and standards (existing file → skip copy). For pack-bundled skills we had to decide the same.

## Options considered

| Option | Pros | Cons |
|---|---|---|
| **Overwrite on pack reinstall** | User always gets latest skill version | Wipes any local customization — surprising and destructive |
| **No-overwrite** (chosen) | Predictable; consistent with other resources; reinstall is safe | User must manually pull skill updates when packs version-bump |

## Resolution

Pack-bundled skills follow the same no-overwrite rule:

- First-time install: copy `pack_root/skills/<name>/` → `<platform_skills_dir>/<name>/`
- Already exists: skip (preserve user's version)
- Result: `apply_pack` returns `skills_added: [...]` listing only newly installed skills

## Future: explicit upgrade

When a future `specflow upgrade` command lands, it can offer an explicit "refresh skills from pack" flag. Until then, users wanting an updated skill must delete the local copy and re-run pack install.
