# Adopt pstack-derived craft-layer practices

## Context

A cross-examination of pstack (poteto's skill stack, github.com/backnotprop/pstack, MIT) and its multi-harness port pstack-claude (github.com/michael-denyer/pstack-claude, MIT) surfaced candidate craft-layer practices. SpecFlow governs when rigor happens (phase lifecycle); it is comparatively weak on the in-flight craft layer. The owner sanctioned the least-controversial subset and is sleeping on the remainder.

Owner sanction (recorded verbatim): "take the least controversial improvement options and have me sleep on the rest".

## Decision

| Track | Practice | Status |
|---|---|---|
| 2 | Lint negative fixtures: every artifact-lint rule id has a test fixture that provably trips it; rule-id set enumerated from source; coverage fails both directions | ADOPTED |
| 2 | Sentence pinning for normative skill text with provenance comments (rule + the DEC that earned it) | ADOPTED |
| 5 | Evidence-labeled claims: measured / inferred / guess in the same sentence; never fabricate artifact IDs or file:line cites | ADOPTED |
| 5 | Never hand the user a check you could run yourself (SpecFlow twist: run the deterministic CLI check — artifact-lint, verify, cascade-status — instead of describing it) | ADOPTED |
| 5 | Frame impact for the consumer and the maintainer before implementation detail | ADOPTED |
| 1 | Decision-trail TSV (`specflow log` append-only per-story log, formula-injection hardening) — source: pstack show-me-your-work | DEFERRED (owner sleeping on it) |
| 3 | Execution playbooks (bug-fix / perf / refactor / prototype / forensics) — source: pstack poteto-mode/playbooks | DEFERRED (owner sleeping on it) |
| 4 | Review synthesis contract (Act / Consider / Noted / Dismissed + agreement map, "diversity is the signal") — source: pstack interrogate | DEFERRED (owner sleeping on it) |
| 6 | Verification feature map (per-REQ user-journey verification; recommended wiring: structured verify-checklist reusing verify_command) — source: pstack create/maintain-verification-skill | DEFERRED (owner sleeping on it) |
| - | Model/effort routing | REJECTED — SpecFlow is model-agnostic; risk tiers already scale ceremony |
| - | TLA+ / Lean verification | REJECTED — repo already ships formal/tla/ + BP-008 |
| - | Benny-style issue triage | REJECTED — defect-from-monitor exists |
| - | Benchmark-checklist | REJECTED — autoresearch guards cover it |
| - | Watch-pr shipping machinery | REJECTED — ship skill + release process cover it |
| - | Multi-harness codegen | REJECTED — byte-identical mirror is simpler and standard-based |

## Consequences

- Adopted tracks land as a test-only change (negative fixtures) and a prose-only change (evidence contract): no engine behavior change, no new gates, no mode toggles.
- The adopted tracks are traceable: REQ/STORY pairs cover both halves.
- Deferred tracks carry design notes in the research handoff and are not started without the owner.
- Rejected tracks are not revisited absent new information contradicting the rationale recorded above.
