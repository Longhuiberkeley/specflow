# Inline execution only — fresh-mode orchestrator/worker deferred

## Context

Autoresearch has two execution modes: **inline** (agent does everything in one session) and **fresh** (orchestrator spawns a worker subagent per iteration to avoid context rot). Fresh mode is the path to 100+ iteration runs.

## Options considered

| Option | Pros | Cons |
|---|---|---|
| **Both modes in v1** | Full feature parity with autoresearch | ~250 extra lines of protocol doc; needs SpecFlow-aware worker subagent; session resume must reconstruct from LOOP + EXPTs |
| **Inline only** (chosen) | Ships sooner; validates the artifact model before scaling up | Bounded to ~30 iterations per session before context rot |

## Resolution

v1 supports **inline execution only**. Agent does all 8 phases in one session.

## Resume workaround

For longer runs, the user creates a **new LOOP** that:
- Has `mode: exploit` (or `explore`, depending on intent)
- Has `knowledge_input` populated with FINDs from the prior LOOP
- Reads the prior LOOP's best_metric / best_experiment for context

The agent in the new session reconstructs state from the LOOP + FINDs + EXPT history without needing autoresearch's `state.json` mechanism.

## v2 path

Fresh mode adapts cleanly to SpecFlow once we decide to ship it:
- Orchestrator reads `specflow trace COMP-NNN` instead of TSV tail
- Worker creates EXPT via `specflow create` instead of TSV append
- Session resume reconstructs from LOOP status + EXPT artifacts

The artifact model is already compatible — only the protocol doc and a worker subagent definition are missing.
