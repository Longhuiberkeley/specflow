stamped summary_warns=0, so without preparation the first post-A2 audit's
trend line would report a fake "+25 warns" regression.

A1 (slice 2/6 of the CHL-344 workstream), the trend-safe prerequisite landed
FIRST so A2's severity unification reads honestly:
- Stamping: new AUD artifacts stamp summary_warns_escalating /
  summary_warns_accounting ALONGSIDE the baseline summary stamp. They are
  deliberately NOT added to _SUMMARY_STAMP_FIELDS — _prior_audit_summary

  only when BOTH the current run and the prior AUD carry the split; either
  side lacking it keeps the legacy total-only rendering — no invented
  numbers. Pure rendering: findings and exit codes untouched.
- known_meta (lib/lint.py) whitelists the two new keys; the audit schema
  (template + dogfood copy) enumerates them in optional_fields, mirroring
  CHL-341's stamp precedent.
- 5 new tests: stamp carries the correct split (mixed structural/accounting
  warns, and the trivial clean-run 0/0), trend renders the split when both
  sides carry it, trend falls back to legacy totals when the prior lacks it,
  _prior_warn_split needs both fields parseable, and an explicit regression
  that an AUD-073-shaped 4-field-only prior still resolves as a full trend
  baseline (not "predates").
