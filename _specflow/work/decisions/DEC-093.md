# ID allocation linearises on exclusive file create; the index is a rebuildable cache; one repo-wide mutation lock

## Decision
Artifact ID allocation linearises on exclusive file creation: `create` opens `PREFIX-NNN.md` with O_EXCL and retries on collision. The candidate id is max(ids present on disk, ids in quarantine, index next_id) + 1. `_index.yaml` becomes a rebuildable cache; REQ-002 section 5's `next_id` is read as a lower-bound hint, not an authoritative counter. One repo-wide mutation lock guards every writer of `_index.yaml`, `state.yaml`, PREV patterns, baselines and impact-log files, through a single `atomic_write` primitive that asserts at runtime that the lock is held; a test bans other writers. `_read_index` rebuilds from disk under the lock when it meets a parse failure or conflict markers and never returns `{next_id: 1}`. The same exclusive-create pattern applies to the PREV, baseline and impact-log allocators. renumber-drafts checks for target collisions, refuses to run on a feature branch, and journals its plan so a crashed run resumes to the same end state as a clean run. The stale-lock break uses `fcntl.flock` on POSIX with the current path as the Windows fallback. merge and split write only statuses legal in the target schema (`superseded` with a `supersedes` link) instead of `merged_into`.

## Rationale
Six defects were reproduced at HEAD 965ac21 on 2026-09-30 in a temporary project: conflict markers in the index make `create` return REQ-001 and overwrite its body; deleting the highest id and rebuilding reuses the id and silently re-binds a STORY's implements link; sixty creates racing sixty updates lose nine creates with a self-consistent index that lint cannot see; a renumber-drafts crash at the second or third write followed by the documented re-run yields duplicate ids, and at the fourth write blocks every later create; cascade-status prints failures and exits 0; merge writes an illegal status. All share one root cause: several unlocked writers read-modify-write an authoritative counter. Locking the counter is weaker than removing it; the file system's exclusive create is the only linearisation point that survives crashes, git merges and parallel agents. This is the design lesson of the formal-methods extraction (SPIKE-003) and the first application of the event-triggered model-checking practice DEC-090 adopted.

## Consequences
- REQ-002 section 5 keeps its wording; DDD-034 records the invariants I1-I6 that make the new reading precise, and the crash and barrier harness in tests/formal/ enforces them on real code.
- Per-type create locks are replaced by one mutation lock; lock ordering questions disappear because renumber is cross-type.
- The disposable TLA+ model in formal/tla/ documents the fixed protocol; it is not a verify contract and is never shipped.
- Consumers see no on-disk change: ids, prefixes and the index layout are unchanged; a rebuilt index is byte-compatible.
- Any future allocator (a new artifact type, a pack ledger) must use the shared primitive or fail the writer-ban test.
