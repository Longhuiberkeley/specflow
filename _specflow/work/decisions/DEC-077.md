# OpenCode consumes .claude/skills; AGENTS.md-only; TLDR default

## Context

OpenCode2 already discovers project `.claude/skills` as a compatibility source. Same skill ID in `.claude/skills` and `.opencode/skills` collapses to one winner (`.opencode` wins). That is a silent per-harness fork, not a double slash command. V2 loads AGENTS.md only (no CLAUDE.md fallback). The injected agent-context block had grown to ~98 lines. The tldr-communication pack only shaped replies if the user remembered `--preset`.

Correction after review: Claude Code does **not** read AGENTS.md natively either (it reads CLAUDE.md only; OpenCode V2 reads AGENTS.md only — the V1 CLAUDE.md fallback is gone in V2). "One instruction file" therefore means AGENTS.md is the single source of truth *plus* a documented `@AGENTS.md` import line in CLAUDE.md so Claude Code still loads it.

## Options

1. Keep copying skills into each host dir (`refresh --all-platforms`).
2. Canonical SpecFlow skills in `.claude/skills`; OpenCode consumes that tree; `.opencode/skills` reserved for different IDs.
3. Fork SKILL.md per host.

## Resolution

Option 2. AGENTS.md is the only instruction file we inject into when the platform lists it; when a `CLAUDE.md` exists we add the documented `@AGENTS.md` import as its first line (idempotent) so Claude Code loads the same guidance — Claude Code reads CLAUDE.md only, OpenCode V2 reads AGENTS.md only. TLDR 4-liner is baseline always-on; the pack remains an optional longer snippet. Plugin work is later and optional.

## Why

Claude Code and OpenCode2 both already read `.claude/skills` + AGENTS.md. Copying a second tree creates drift the user will not notice.
