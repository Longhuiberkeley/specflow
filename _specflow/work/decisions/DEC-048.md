# FINDING updates are manual, agent-driven (no auto-aggregation in v1)

## Context

After a LOOP completes there are ~30-50 EXPTs to condense into FINDs. Two paths considered.

## Options considered

| Option | Pros | Cons |
|---|---|---|
| **Auto-aggregation script** | One command produces draft FINDs | Requires `specflow query` API that doesn't exist; brittle templates; agent still has to review |
| **Manual, agent-driven** (chosen) | Works today; agent reads EXPTs directly; flexible across domains | More effort per LOOP completion |

## Resolution

After a LOOP completes, the skill's protocol directs the agent to:

1. Read all EXPTs in the LOOP (filtered by `loop: LOOP-NNN`)
2. Identify patterns by `change_category` distribution
3. Run `specflow create --type finding --status draft` for new insights
4. Run `specflow update FIND-NNN --status superseded` for outdated FINDs (then create the refined version)

`finding-generation-protocol.md` documents the playbook in detail.

## Future work (deferred)

Once a `specflow query` capability lands, auto-draft generation becomes a simple aggregation pipeline. The schema is already structured for that future.
