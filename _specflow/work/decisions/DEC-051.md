# STRAT is not an artifact type — strategies remain code-level concepts

## Context

A strategy (e.g., `@register("STRAT-104")` in Python) is a code-level approach that an EXPT might use. We considered making it a first-class artifact.

## Options considered

| Option | Pros | Cons |
|---|---|---|
| **STRAT as artifact type** | Full traceability from strategy to experiment | Overhead during loop — agent must create/maintain STRAT artifacts per iteration; strategies change too rapidly to be worth tracking as specs |
| **Plain string reference** (chosen) | Zero overhead; EXPT's `strategy_used` field records which strategy was used | No strategy-level aggregation (acceptable in v1) |

## Resolution

Strategies are code concepts, not SpecFlow artifacts. EXPT artifacts reference strategies via the plain `strategy_used` optional field (a string like `"STRAT-104"`). No STRAT schema, no STRAT directory, no STRAT lifecycle.
