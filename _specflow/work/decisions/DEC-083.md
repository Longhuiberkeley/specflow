# Skill standards are artifact-native: progressive disclosure, router bodies, bare specflow CLI

## Decision

The normative skill standards live in the artifact system (this DEC + ARCH-030), not in `docs/skill-standards.md`. `docs/` is at most a derived pointer (DEC-082).

### Normative rules

1. **Progressive disclosure.** Skills fiercely protect the context window: the SKILL.md frontmatter `description` is the only routing surface and must be a one-line narrow trigger (the situation where the skill is REQUIRED) — no keyword walls, no NOT-for lists.
2. **SKILL.md is a lean router.** Imperative, high-level instructions under 500 lines; no deep domain knowledge or large checklists in the body. Domain knowledge lives in `references/` and is read only when the router points at it for the current context.
3. **Single generalized agent.** No explicit personas (PM/Architect). The skill guides one agent to scale ceremony with the ambiguity of the request.
4. **Deterministic operations are delegated, not reimplemented.** SpecFlow is Python-primary (D-16/D-17): validation, fingerprints, ranking, and formatting run in the `specflow` CLI. Skills invoke bare `specflow <cmd>` — never `uv run specflow`, which only works where specflow is a declared project dependency. A skill may carry `scripts/` only for genuine per-skill tooling (today only specflow-pack-author); the norm is CLI delegation.
5. **Template layering.** What ships is `src/specflow/templates/skills/shared/<skill>/`; the dogfood copy is `.claude/skills/<skill>/`; the two are kept byte-identical. `specflow init`/`refresh` copy templates to each host's skill dir; packs install skills via `apply_pack` (never overwriting user edits).

## Consequences

- One knowledge graph: brief/trace/lint cover what models are told about writing skills.
- Enforcement is testable: the <500-line cap and description shape are pinned in tests (pytest), not prompt text.
- `docs/skill-standards.md` becomes a short derived pointer; AGENTS.md section 5 cites the artifacts.
