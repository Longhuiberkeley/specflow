# Consistency-review decisions D1–D6: approvals carve-out, release ledger steps, adoption baseline name, open status categories, severity mapping, GitHub gate wording

# Consistency-review decisions (SPIKE-008)

## Context
SPIKE-008 (two-round read-only review of v1.17.6) left six decisions to the owner. Three independent reviewers assessed each; GitHub behaviour was checked against docs.github.com (required status checks, CODEOWNERS, workflow syntax).

## Decisions
- **D1 Approvals.** Keep the delegated-autonomy clause (REQ-042 R3, `tests/test_approval_guardrail.py`). Narrow it once in `specflow-references/references/approval-presentation.md`: only the direct user in the current session can delegate; never for a release or any risk-tier 2 action. Each skill gate points at that sentence. Ship keeps its absolute wording. Rejected: deleting the clause (breaks REQ-042 R3); dogfood-only copy (the clause lives inside the auto-generated AGENTS.md block, overwritten by `refresh`).
- **D2 Release process.** AGENTS.md release steps gain `specflow document-changes --since <prev-tag>`, `specflow baseline create v<ver> --evidence`, `specflow phase-set complete --reason "released v<ver>"` before the release commit. No backfill of v1.17.2..v1.17.6: `create_baseline` snapshots the current ledger, so backfilled files would be identical copies under old tag SHAs, write-once. v1.17.7 pairs with v1.17.1.
- **D3 Adoption baseline name.** `v0.0.0-adoption.<n>`; the highest n is the headline. It always satisfies `_SEMVER_NAME_RE`, sorts below every real release, and checkpoints sort in time order. `v<project-version>-adoption` rejected (fails for dev/rc versions, many repos have no version); regex exemption rejected (freeform names fall to the raw tail and reverse the drift direction). Legacy `adoption-v0.yaml` stays valid; anchor with `project-audit --baseline adoption-v0`. A test validates every baseline name in shipped prose.
- **D4 Status categories.** Engine fix per REQ-033: known four rows first, extra schema categories sorted after; `brief` uses the same open set. No DEC ever closed the set.
- **D5 Severity vocabulary.** Document the existing `error/warn/info → blocking/warning/info` mapping (`core/findings.py:89`) in severity-levels.md; fix `_severity_rank` so `warning` ranks as `warn`. Full unification deferred to a minor release (80+ sites, 8 test files, consumer CHL data).
- **D6 GitHub gate.** Measured from GitHub docs: required checks are selected by the job display name (`name:`), a required check skipped by `if:` counts as passing, several owners on one CODEOWNERS line means any one approval suffices. Therefore: keep every generated job name; docs and the adapter reference require both "Pass 1 — programmatic validation" (`specflow-pass-1`) and "CI gate (RBAC)" (`specflow-ci-gate`); `ci-gate` joins the default `ci.operations` (no-roles shortcut keeps solo projects green; `refresh` never regenerates workflows); job order becomes deterministic; CODEOWNERS stays one line and is documented as any-of, with role separation enforced by ci-gate. Dropping `name:` keys rejected (would stall every consumer PR already requiring the display names).

## Consequences
REQ-070 is guided by this DEC. Out of scope for v1.17.7 and recorded in SPIKE-008: ARCH/DDD rewrites, test-spec promotion, output_files sweep, severity unification, STORY-035 descope.
