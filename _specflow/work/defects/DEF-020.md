# specflow go stages the whole working tree and reports Completed for stories it never executed

## Symptom

`specflow go` without `--dry-run` reports every approved story in the wave as `Completed` and then runs `git add -A && git commit -m "specflow: wave N prepared [...]"`.

## Measured (v1.17.4)

- `src/specflow/lib/executor.py` `execute_story` is a stub: it assembles context and returns `{"ok": True, "detail": "Context assembled for ..."}` for every story; the AI host does the work.
- `run_execution` appends every `ok` story to `state.completed` and, when any story was ready, calls `auto_commit_wave`, which runs `git add -A` then `git commit` (executor.py:192-207).
- `src/specflow/commands/go.py:65` prints `Completed: <ids>` from `state.completed`.
- `tests/test_go_executor.py::TestAutoCommitWave::test_commits_pending_changes_with_wave_message` pins the blanket staging as intended behaviour.

## Impact

Consumer: a user who runs `go` to "execute the wave" sees a green Completed list for work that never happened, and every unrelated uncommitted file in the tree is swept into a misleading wave commit. Maintainer: the dirty-tree hazard was live during the v1.17.4 release window with 37 uncommitted paths.

## Expected

`go` assembles context and says so; it never stages or commits. REQ-001 §6 "Auto-commit per task completion" is amended by DEC-103.
