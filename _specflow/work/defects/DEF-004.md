# Verify-run readers disagree on the expected exit code (planned DEF-010)

# Verify-run readers disagree on the expected exit code

## Observed
Four readers re-derived the pass rule for a recorded verify run and disagreed. brief (_next_skill_recommendation verify advisory) only flagged a run as diverged when verify_exit_code was declared, so a run exiting 1 with no declared code was silently treated as fine. evidence (_test_results_section) compared verify_run_exit_code to a hard-coded "0", ignoring the declared code. risk tier and project audit used the declared code with default 0 (correct).

## Expected
Per ARCH-026 (verify_exit_code default 0) and REQ-058 AC1, a run passes exactly when its exit code equals the declared verify_exit_code, default 0, through one shared helper. This is a false-confidence signal against REQ-037.

## Fix
STORY-699: lib/verification.run_matches_expected(frontmatter) -> bool | None is the one rule; brief, evidence, risk tier and both project-audit readers (verification lens, ac-coverage green count) call it. Regression tests: tests/test_run_matches_expected.py (UT-126) and tests/test_verify_expected_exit_cli.py (IT-090).
