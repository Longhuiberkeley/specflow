# REQ-010 EARS verification drift: QT-011 cites an absent test

## Observed
QT-011 (EARS Quality in Prompts and Lint Qualification) is implemented and verifies REQ-010, but its Test Reference names tests/test_ears_quality.py, which does not exist in the repository, and it declares no verify_command. Nothing surfaced the dead reference: no lint check looked at whether a verification oracle names a real file.

## Analysis
REQ-010 has two halves. Part A (prompt guidance: EARS patterns, ambiguity list, compound-shall and passive-voice guidance in normative-language.md) was intentionally trimmed when REQ-042 turned lifecycle skills into lean routers (commit be17ee6, STORY-658/659); that trim is a recorded product decision, not a regression, and is noted here rather than restored. Part B (the deterministic artifact-lint quality check: ambiguity words, passive voice, compound shall, missing thresholds, warning severity) is intact and covered by tests/test_quality_lint.py. The drift is purely in the verification artifact: QT-011 pointed at a test file that never existed under that name.

## Fix
STORY-699: QT-011 verify_command repointed to uv run pytest tests/test_quality_lint.py -q and its Test Reference updated to the same file (the TC-001 prompt-guidance case records the REQ-042 trim). The new artifact-lint dead-oracle accounting check (warning only, never feeds project-audit exit 2) reports any verify_command token that looks like a repository path and does not exist. Regression tests: tests/test_dead_oracle.py (UT-127).
