# No-flock mutation-lock fallback keeps the stale-break window: two processes hold the lock

The DEF-010 fix moved the POSIX mutation lock to fcntl.flock and left the file-based stale break as the Windows fallback, which keeps the re-read-to-unlink window DEF-010 describes. Reproduced on POSIX by removing fcntl from locks.py in a barrier worker. Fix: on the no-flock path take a kernel byte-range lock (msvcrt.locking) on the lock file, released by the OS when the holder dies, instead of the stale-file break.
