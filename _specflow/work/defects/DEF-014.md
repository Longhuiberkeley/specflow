# An id erased from every working-tree record is reallocated: hand delete plus a merge conflict on _index.yaml resolved with the other side re-binds existing links

Found by TLC on the fixed-protocol model formal/tla/IdAllocation.tla (SPIKE-003 part 2) and replayed on the real code by UT-132 (strict xfail). Every allocation floor lives in the working tree (file stems, index keys, quarantine, next_id). A delete that never went through rebuild-index leaves no quarantine entry, and a conflict resolved with the older side of _index.yaml lowers next_id, so nothing remembers the id. The conflict-marker path is safe: _read_index salvages both sides. Candidate remedies, owner decision: (a) state it as a DDD-034 environment assumption (resolve _index.yaml conflicts by running rebuild-index, never --theirs); (b) also floor on link targets that name the type prefix, which covers ids that are still referenced; (c) floor on git history. Not fixed in this package.
