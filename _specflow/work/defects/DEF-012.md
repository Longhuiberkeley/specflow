# merge wrote the non-schema status merged_into straight into the source file, bypassing update_artifact

## Defect
specflow merge set the source artifact to status merged_into by rewriting its frontmatter directly. merged_into is not in any shipped allowed_status map, so the artifact left the lifecycle (transitions, lint status checks and the index all disagreed), and the write skipped update_artifact, the only place that enforces legal transitions.

## Pre-fix behaviour (v1.16.0, recorded before W-A landed the fix in this cycle)
- test_merge_cli_supersedes_an_approved_source: source status merged_into, not superseded; no supersedes link on the target.
- test_merge_of_a_draft_source_uses_the_legal_cancelled: draft source became merged_into.
- test_merge_never_writes_a_status_outside_the_schema: merged_into is not in allowed_status.
- test_merge_and_split_never_write_status_directly[lib/impact.py] and test_status_write_ban::test_no_status_write_outside_update_artifact: lib/impact.py:529 and the cli.py merge help string.

## Fix
Landed by the STORY-696 package (W-A) in this cycle: merge adds a supersedes link on the target and moves the source to superseded through update_artifact, or to cancelled/deprecated where superseded is not legal from its status; split writes no status. STORY-697 adds the repo-wide grep ban (UT-131) so no module outside lib/artifacts.py writes status again.
