# cascade-status proposes illegal transitions (approved to verified, self-loops), promotes a REQ past an unverified sibling STORY, and exits 0 on failure

## Defect
cascade-status computed one target status per spec and wrote it in a single hop, without consulting the target schema: approved -> verified is not an allowed_status edge, so the write was refused. The refusal was printed with a cross but the command returned 0, so hooks, reconcile and skills treated a failed cascade as success. REQ promotion to verified ignored sibling STORYs implementing the same REQ (closure rule), and the role set (implements only) disagreed with the status-cascade lint (implements + derives_from).

## Root cause
commands/cascade_status.py:72-77 chose req_status = verified whenever the triggering STORY was verified; :92-104 printed the update error and fell through to return 0. The ARCH/DDD role checks were duplicated inline in artifact_lint._check_status_cascade.

## Fix
One CASCADE_ROLES set shared with the lint; a legal_walk planner that walks approved -> implemented -> verified one schema edge at a time or refuses; the closure hold; exit 1 on any refused or failed transition.
